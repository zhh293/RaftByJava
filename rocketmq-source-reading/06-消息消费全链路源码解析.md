## 2. 消费架构设计（"push" = pull）

### 2.1 Push 模式的本质

RocketMQ 的 Push 模式消费者（`DefaultMQPushConsumer`）并非真正意义上的"服务端推送"，而是一个**伪装成 Push 的 Pull 消费者**。其核心设计思想是：

1. **消费者主动拉取**：消费者通过 `PullMessageService` 不断向 Broker 发起 Pull 请求
2. **Broker 端长轮询**：当 Broker 没有新消息时，不是立即返回 NOT_FOUND，而是将请求挂起（suspend），最长挂起 15 秒（`BROKER_SUSPEND_MAX_TIME_MILLIS`）
3. **新消息唤醒**：当新消息到达时，Broker 立即唤醒挂起的请求并返回消息
4. **消费者立即再拉**：消费者处理完一批消息后立即再次发起 Pull 请求

这种设计在用户视角上表现为"消息自动推送过来"，但底层完全是 Pull 机制。

### 2.2 为什么不直接用 Push？

| 维度 | 纯 Push | Pull + 长轮询（RocketMQ 方案） |
|------|---------|------|
| 流量控制 | 服务端控制推送速率，容易压垮消费者 | 消费者自己控制拉取速率，天然背压 |
| 消费者能力适配 | 无法感知消费者处理能力 | 消费者处理完才拉下一批 |
| 实现复杂度 | 需要维护连接状态、推送队列 | 简单的请求-响应模型 |
| 可靠性 | 推送失败需要重推机制 | 拉取失败重新拉取即可 |
| 资源利用 | 消费者空闲时仍被推送 | 消费者自己决定何时拉取 |

### 2.3 Push 消费者初始化

```java
// DefaultMQPushConsumerImpl.start() 中的关键初始化逻辑
public synchronized void start() throws MQClientException {
    switch (this.serviceState) {
        case CREATE_JUST:
            this.serviceState = ServiceState.START_FAILED;
            this.checkConfig();

            // 复制订阅关系
            this.copySubscription();

            // 设置消费者组实例名
            if (null == this.messageModel) {
                this.messageModel = MessageModel.CLUSTERING;
            }

            // 分配策略默认为平均分配
            if (null == this.allocateMessageQueueStrategy) {
                this.allocateMessageQueueStrategy =
                    new AllocateMessageQueueAveragely();
            }

            // 创建 MQClientInstance（单例，每个 clientId 一个）
            this.mQClientFactory = MQClientManager.getInstance()
                .getOrCreateMQClientInstance(this.defaultMQPushConsumer, this.rpcHook);

            // 设置 RebalanceImpl
            this.rebalanceImpl.setConsumerGroup(this.defaultMQPushConsumer
                .getConsumerGroup());
            this.rebalanceImpl.setMessageModel(this.messageModel);
            this.rebalanceImpl.setAllocateMessageQueueStrategy(
                this.allocateMessageQueueStrategy);
            this.rebalanceImpl.setmQClientFactory(this.mQClientFactory);

            // 创建 PullAPIWrapper
            this.pullAPIWrapper = new PullAPIWrapper(
                mQClientFactory,
                this.defaultMQPushConsumer.getConsumerGroup(),
                this.isUnitMode());
            this.pullAPIWrapper.registerFilterMessageHook(filterMessageHookList);

            // 根据消费模式创建 OffsetStore
            if (this.defaultMQPushConsumer.getOffsetStore() == null) {
                if (CLOUDING_MODE) {
                    // 广播模式（特殊云端模式）
                } else {
                    switch (this.messageModel) {
                        case BROADCASTING:
                            this.offsetStore = new LocalFileOffsetStore(
                                this.mQClientFactory,
                                this.defaultMQPushConsumer.getConsumerGroup());
                            break;
                        case CLUSTERING:
                            this.offsetStore = new RemoteBrokerOffsetStore(
                                this.mQClientFactory,
                                this.defaultMQPushConsumer.getConsumerGroup());
                            break;
                        default:
                            break;
                    }
                }
            }
            this.defaultMQPushConsumer.setOffsetStore(this.offsetStore);
            this.offsetStore.load();

            // 创建消费服务
            if (this.getMessageListenerInner() instanceof MessageListenerOrderly) {
                this.consumeMessageService = new ConsumeMessageOrderlyService(
                    this, (MessageListenerOrderly) this.getMessageListenerInner());
            } else if (this.getMessageListenerInner()
                       instanceof MessageListenerConcurrently) {
                this.consumeMessageService = new ConsumeMessageConcurrentlyService(
                    this, (MessageListenerConcurrently) this.getMessageListenerInner());
            }
            this.consumeMessageService.start();

            // 注册消费者到 MQClientInstance
            boolean registerOK = mQClientFactory.registerConsumer(
                this.defaultMQPushConsumer.getConsumerGroup(), this);
            if (!registerOK) {
                throw new MQClientException(...);
            }

            // 启动 MQClientInstance（启动 Rebalance、PullMessageService 等）
            mQClientFactory.start();

            this.serviceState = ServiceState.RUNNING;
            break;
        default:
            break;
    }

    // 触发一次 Rebalance
    this.updateTopicSubscribeInfoWhenSubscriptionChanged();
    try {
        this.mQClientFactory.checkClientInNetwork();
    } catch (Exception e) {
        // ...
    }
    this.mQClientFactory.sendHeartbeatToAllBrokerWithLock();
    this.mQClientFactory.rebalanceImmediately();
}
```

### 2.4 MQClientInstance 启动的重要组件

`MQClientInstance.start()` 启动了多个后台线程：

```java
public void start() throws MQClientException {
    synchronized (this) {
        switch (this.serviceState) {
            case CREATE_JUST:
                this.serviceState = ServiceState.START_FAILED;

                // 1. 获取 NameServer 地址
                if (null == this.clientConfig.getNamesrvAddr()) {

                this.defaultMQProducer.getDefaultMQProducerImpl()
                    .start(false);

                this.serviceState = ServiceState.RUNNING;
                break;
            default:
                break;
        }
    }
}
```

### 2.5 RebalanceService 定时触发

`RebalanceService` 是一个继承 `ServiceThread` 的后台线程，默认每 20 秒执行一次 Rebalance：

```java
public class RebalanceService extends ServiceThread {
    private static long waitInterval =
        Long.parseLong(System.getProperty(
            "rocketmq.client.rebalance.waitInterval", "20000"));
    private final MQClientInstance mqClientFactory;

    public RebalanceService(MQClientInstance mqClientFactory) {
        this.mqClientFactory = mqClientFactory;
    }

    @Override
    public void run() {
        log.info(this.getServiceName() + " service started");

        while (!this.isStopped()) {
            this.waitForRunning(waitInterval);
            this.mqClientFactory.doRebalance();
        }

        log.info(this.getServiceName() + " service end");
    }

    @Override
    public String getServiceName() {
        return RebalanceService.class.getSimpleName();
    }
}
```

`MQClientInstance.doRebalance()` 遍历所有消费者执行 Rebalance：

```java
public void doRebalance() {

        if (impl != null) {
            try {
                impl.doRebalance();
            } catch (Throwable e) {
                log.error("doRebalance exception", e);
            }
        }
    }
}
```

## 3. RebalanceImpl 队列分配

### 3.1 doRebalance 入口

`RebalanceImpl.doRebalance()` 是队列分配的入口方法：

```java
// RebalanceImpl.java
public void doRebalance(final boolean isOrder) {
    Map<String, SubscriptionData> subTable = this.getSubscriptionInner();
    if (subTable != null) {
        for (final Map.Entry<String, SubscriptionData> entry : subTable.entrySet()) {
            final String topic = entry.getKey();
            try {
                // 对每个订阅的 Topic 执行 Rebalance
                this.rebalanceByTopic(topic, isOrder);
            } catch (Throwable e) {
                if (!topic.startsWith(MixAll.RETRY_GROUP_TOPIC_PREFIX)) {
                    log.warn("rebalanceByTopic Exception", e);
                }
            }
        }
    }

    // 移除不再订阅的 Topic 对应的 ProcessQueue
    this.truncateMessageQueueNotInSubscribe();
}
```

### 3.2 rebalanceByTopic 核心逻辑

`rebalanceByTopic` 根据 MessageModel 分为广播模式和集群模式两种处理路径：

```java
// RebalanceImpl.java
private void rebalanceByTopic(final String topic, final boolean isOrder) {
    switch (messageModel) {
        case BROADCASTING: {
            // 广播模式：所有消费者消费所有 MessageQueue
            Set<MessageQueue> mqSet = this.topicSubscribeInfoTable.get(topic);
            if (mqSet != null) {
                // 直接使用全部 MessageQueue
                boolean changed = this.updateProcessQueueTableInRebalance(
                    topic, mqSet, isOrder);
                if (changed) {
                    this.messageQueueChanged(topic, mqSet, mqSet);
                    log.info("messageQueueChanged {} {} {} {}",
                        consumerGroup, topic, mqSet, mqSet);
                }
            } else {
                log.warn("doRebalance, {}, but the topic[{}] not exist.",
                    consumerGroup, topic);
            }
            break;
        }
        case CLUSTERING: {
            // 集群模式：需要分配
            // 1. 获取该 Topic 的所有 MessageQueue
            Set<MessageQueue> mqSet = this.topicSubscribeInfoTable.get(topic);
            // 2. 获取该消费者组下所有消费者客户端 ID
            List<String> cidAll = this.mQClientFactory.findConsumerIdList(
                topic, consumerGroup);
            if (null == mqSet) {
                if (!topic.startsWith(MixAll.RETRY_GROUP_TOPIC_PREFIX)) {
                    log.warn("doRebalance, {}, but the topic[{}] not exist.",
                        consumerGroup, topic);
                }
            }

            if (null == cidAll) {
                log.warn("doRebalance, {} {} get consumer id list failed",
                    consumerGroup, topic);
            }

            if (mqSet != null && cidAll != null) {
                List<MessageQueue> mqAll = new ArrayList<>(mqSet);
                Collections.sort(mqAll);
                Collections.sort(cidAll);

                AllocateMessageQueueStrategy strategy = this.allocateMessageQueueStrategy;

                List<MessageQueue> allocateResult = null;
                try {
                    allocateResult = strategy.allocate(
                        this.consumerGroup,
                        this.mQClientFactory.getClientId(),
                        mqAll,
                        cidAll);
                } catch (Throwable e) {
                    log.error("allocateMessageQueue exception. strategyName={}",
                        strategy.getName(), e);
                    return;
                }

                Set<MessageQueue> allocateResultSet = new HashSet<>();
                if (allocateResult != null) {
                    allocateResultSet.addAll(allocateResult);
                }

                // 更新 ProcessQueue 表
                boolean changed = this.updateProcessQueueTableInRebalance(
                    topic, allocateResultSet, isOrder);
                if (changed) {
                    log.info(
                        "client rebalanced result. strategyName={}, "
                        + "consumerGroup={}, clientId={}, mqAllSize={}, "
                        + "cidAllSize={}, rebalanceResultSize={}, "
                        + "rebalanceResultSet={}",
                        strategy.getName(), consumerGroup,
                        this.mQClientFactory.getClientId(),
                        mqAll.size(), cidAll.size(),
                        allocateResultSet.size(),
                        JsonUtil.toJson(allocateResultSet));
                    this.messageQueueChanged(topic, mqSet, allocateResultSet);
                }
            }
            break;
        }
        default:
            break;
    }
}
```

#### 3.2.1 集群模式的核心流程

在 CLUSTERING 模式下，Rebalance 的核心流程为：

1. **获取 MessageQueue 列表**：从 `topicSubscribeInfoTable` 中获取该 Topic 的所有 MessageQueue。这个信息来源于从 NameServer 拉取的路由信息。
2. **获取消费者 ID 列表**：通过 `findConsumerIdList` 向 Broker 发送 `GET_CONSUMER_LIST_BY_GROUP` 请求，获取同一消费者组下所有活跃消费者的客户端 ID。
3. **排序**：对 `mqAll` 和 `cidAll` 都进行排序，确保所有消费者看到相同的顺序，这是正确分配的基础。
4. **分配策略执行**：调用 `allocateMessageQueueStrategy.allocate()` 计算当前消费者应该消费哪些 MessageQueue。
5. **更新 ProcessQueue 表**：将分配结果传入 `updateProcessQueueTableInRebalance`。

### 3.4 updateProcessQueueTableInRebalance（行 426）

这是 Rebalance 中最关键的方法之一。它对比当前消费者已拥有的 MessageQueue 和新分配的 MessageQueue，新增分配到的队列、移除不再分配的队列：

```java
// RebalanceImpl.java (约 line 426)
private boolean updateProcessQueueTableInRebalance(final String topic,
        final Set<MessageQueue> mqSet, final boolean isOrder) {
    boolean changed = false;

    // 1. 移除不再分配的 ProcessQueue
    // 遍历当前 processQueueTable，移除不在新分配集合中的 MessageQueue
    Iterator<Map.Entry<MessageQueue, ProcessQueue>> it =
        this.processQueueTable.entrySet().iterator();
    while (it.hasNext()) {
        Map.Entry<MessageQueue, ProcessQueue> next = it.next();
        MessageQueue mq = next.getKey();
        ProcessQueue pq = next.getValue();

        if (mq.getTopic().equals(topic)) {
            if (!mqSet.contains(mq)) {
                // 新分配集合中不包含此 MessageQueue，需要移除
                pq.setDropped(true);
                this.removeProcessQueue(mq);  // 移除并持久化偏移量
                if (this.removeUnnecessaryMessageQueue(mq, pq)) {
                    it.remove();
                    changed = true;
                    log.info("doRebalance, {}, remove unnecessary mq, {}",
                        consumerGroup, mq);
                }
            } else if (pq.isPullExpired()) {
                // 拉取过期，也需要移除
                pq.setDropped(true);
                this.removeProcessQueue(mq);
                if (this.removeUnnecessaryMessageQueue(mq, pq)) {
                    it.remove();
                    changed = true;
                    log.info("doRebalance, {}, remove expired mq, {}",
                        consumerGroup, mq);
                }
            }
        }
    }

    // 2. 为新分配的 MessageQueue 创建 ProcessQueue 和 PullRequest
    List<PullRequest> pullRequestList = new ArrayList<>();
    for (MessageQueue mq : mqSet) {
        if (!this.processQueueTable.containsKey(mq)) {
            // 新分配到的 MessageQueue，之前不在 processQueueTable 中
            if (isOrder && !this.lock(mq)) {
                // 顺序消费需要先获取分布式锁
                log.warn("doRebalance, {}, add a new mq failed, {}, because lock failed",
                    consumerGroup, mq);
                continue;
            }

            // 创建 ProcessQueue
            ProcessQueue pq = new ProcessQueue();
            pq.setLastPullTimestamp(System.currentTimeMillis());

            // 计算从哪个偏移量开始拉取
            long nextOffset = -1L;
            try {
                nextOffset = this.computePullFromWhereWithException(mq);
            } catch (Exception e) {
                log.info("doRebalance, {}, computePullFromWhereWithException exception",
                    consumerGroup, mq, e);
                continue;
            }

            if (nextOffset >= 0) {
                // 确认偏移量有效，注册 ProcessQueue
                ProcessQueue oldPq = this.processQueueTable.putIfAbsent(mq, pq);
                if (oldPq != null) {
                    // 已存在，跳过（并发竞争）
                    log.info("doRebalance, {}, mq already exists, {}", consumerGroup, mq);
                } else {
                    // 成功注册，创建 PullRequest
                    log.info("doRebalance, {}, add a new mq, {}", consumerGroup, mq);
                    PullRequest pullRequest = new PullRequest();
                    pullRequest.setConsumerGroup(consumerGroup);
                    pullRequest.setNextOffset(nextOffset);
                    pullRequest.setMessageQueue(mq);
                    pullRequest.setProcessQueue(pq);

                    pullRequestList.add(pullRequest);
                    changed = true;
                }
            } else {
                log.warn("doRebalance, {}, add new mq failed, {}",
                    consumerGroup, mq);
            }
        }
    }

    // 3. 分发 PullRequest
    if (!pullRequestList.isEmpty()) {
        this.dispatchPullRequest(pullRequestList, 500);
    }

    return changed;
}
```

#### 3.4.1 关键设计分析

**为什么要先移除再新增？**

`updateProcessQueueTableInRebalance` 的设计是先遍历移除不再需要的 MessageQueue，再遍历新增新分配的 MessageQueue。这个顺序很重要：

1. **先移除**：确保释放不再需要的队列资源（ProcessQueue 中的消息、锁等）
2. **后新增**：为新分配的队列创建 ProcessQueue 和初始 PullRequest

**computePullFromWhere 计算起始偏移量**

```java
// RebalanceImpl.java
public long computePullFromWhere(MessageQueue mq) {
    long result = -1L;
    final ConsumeFromWhere consumeFromWhere = this.defaultMQPushConsumerImpl
        .getDefaultMQPushConsumer().getConsumeFromWhere();

    // 从 OffsetStore 读取偏移量
    long lastOffset = this.offsetStore.readOffset(mq,
        OffsetStore.READ_FROM_STORE);

    if (lastOffset >= 0) {
        // 之前消费过，从上次的位置继续
        result = lastOffset;
    } else {
        // 之前没有消费记录
        switch (consumeFromWhere) {
            case CONSUME_FROM_LAST_OFFSET_AND_FROM_MIN_WHEN_BOOT_FIRST:
                // 从最后一个偏移量开始
            case CONSUME_FROM_LAST_OFFSET: {
                // 从最后位置开始消费（默认）
                result = this.offsetStore.readOffset(mq,
                    OffsetStore.READ_FROM_MEMORY);
                if (result < 0) {
                    // 内存中没有，从 Broker 查询
                    result = this.offsetStore.readOffset(mq,
                        OffsetStore.READ_FROM_STORE);
                }
                if (result < 0) {
                    // 查询 Broker 的最大偏移量
                    try {
                        result = this.mQClientFactory.getMQAdminImpl()
                            .maxOffset(mq);
                    } catch (Exception e) {
                        result = -1;
                    }
                }
                break;
            }
            case CONSUME_FROM_FIRST_OFFSET: {
                // 从最小偏移量开始消费
                result = 0L;
                break;
            }
            case CONSUME_FROM_TIMESTAMP: {
                // 从指定时间戳开始消费
                // ...
                break;
            }
            default:
                break;
        }
    }

    return result;
}
```

```java
    if (this.defaultMQPushConsumerImpl.isConsumeOrderly()) {

        synchronized (pq.getLock()) {
```

### 4.2 AllocateMessageQueueAveragely 平均分配

这是默认的分配策略，将 MessageQueue 尽可能均匀地分配给所有消费者：

```java
// AllocateMessageQueueAveragely.java
public class AllocateMessageQueueAveragely
        implements AllocateMessageQueueStrategy {

    @Override
    public List<MessageQueue> allocate(String consumerGroup, String currentCID,
            List<MessageQueue> mqAll, List<String> cidAll) {

        // 参数校验
        List<MessageQueue> result = new ArrayList<>();
        if (!check(consumerGroup, currentCID, mqAll, cidAll)) {
            return result;
        }

        // 当前消费者在 cidAll 中的索引位置
        int index = cidAll.indexOf(currentCID);

        // 取模：不能整除时的余数
        int mod = mqAll.size() % cidAll.size();

        // 计算每个消费者应该分配的队列数量
        // 如果有余数，前 mod 个消费者各多分配一个
        int averageSize =
            mqAll.size() <= cidAll.size() ? 1 :
            (mod != 0 && index < mod ? mqAll.size() / cidAll.size() + 1
                                     : mqAll.size() / cidAll.size());

        // 计算起始索引
        int startIndex = (mod != 0 && index < mod) ?
            index * averageSize :
            index * averageSize + mod;

        // 计算实际范围
        int range = Math.min(averageSize, mqAll.size() - startIndex);

        for (int i = 0; i < range; i++) {
            result.add(mqAll.get((startIndex + i) % mqAll.size()));
        }

        return result;
    }

    @Override
    public String getName() {
        return "AVG";
    }
}
```

### 5.3 run 方法 - 单线程拉取循环

```java
// PullMessageService.java
@Override
public void run() {
    log.info(this.getServiceName() + " service started");

    while (!this.isStopped()) {
        try {
            // 从队列中取出拉取请求（阻塞）
            MessageRequest messageRequest = this.messageRequestQueue.take();

            if (messageRequest == null) {
                continue;
            }

            boolean cancelled = false;
            try {
                // 判断请求类型
                if (messageRequest instanceof PullRequest) {
                    // 普通拉取请求
                    this.pullMessage((PullRequest) messageRequest);
                } else if (messageRequest instanceof PopRequest) {
                    // Pop 拉取请求（轻量级拉取，减少长轮询开销）
                    this.popMessage((PopRequest) messageRequest);
                } else {
                    log.warn("Unknown messageRequest type: {}",
                        messageRequest.getClass().getName());
                }
            } catch (Exception e) {
                log.error("Pull Message Service Run Method exception", e);
                cancelled = true;
            }

            // 如果执行过程中发生异常，延迟重新入队
            if (cancelled) {
                if (messageRequest instanceof PullRequest) {
                    PullRequest pullRequest = (PullRequest) messageRequest;
                    // 检查 ProcessQueue 是否已被丢弃
                    if (pullRequest.getProcessQueue() != null
                        && !pullRequest.getProcessQueue().isDropped()) {
                        // 延迟 3 秒重新拉取
                        this.executePullRequestLater(pullRequest, 3000);
                    }
                }
            }
        } catch (InterruptedException e) {
            // 被 interrupt 中断，正常退出
        }
    }

    log.info(this.getServiceName() + " service end");
}
```

### 5.4 pullMessage 委托给消费者实现

```java
// PullMessageService.java
private void pullMessage(final PullRequest pullRequest) {
    // 获取消费者实现
    final MQConsumerInner consumer = this.mQClientFactory
        .selectConsumer(pullRequest.getConsumerGroup());
    if (consumer != null) {
        DefaultMQPushConsumerImpl impl =
            (DefaultMQPushConsumerImpl) consumer;
        // 委托给消费者的 pullMessage 方法
        impl.pullMessage(pullRequest);
    } else {
        log.warn(
            "No matched consumer for the PullRequest {}, drop it",
            pullRequest);
    }
}
```

### 5.6 设计要点分析

**为什么用单线程？**

`PullMessageService` 使用单线程从队列中取出请求，但实际的 Pull 操作是异步的（通过 Netty 异步调用）。这意味着：

1. 单线程只负责调度，不阻塞在网络 IO 上
2. 异步拉取完成后通过回调处理结果
3. 多个 PullRequest 可以同时在网络传输中

这形成了一个**生产者-消费者**模型：
- **生产者**：Rebalance 产生 PullRequest，PullCallback 处理完后重新入队
- **消费者**：`PullMessageService.run()` 单线程取出并执行

```
┌─────────────┐     put      ┌───────────────────────┐     take      ┌─────────────┐
│ Rebalance   │─────────────▶│ LinkedBlockingQueue    │──────────────▶│ run()       │
│ PullCallback│              │ <MessageRequest>       │               │ pullMessage │
│             │              │ (无界队列)              │               │ (异步)       │
└─────────────┘              └───────────────────────┘               └──────┬──────┘
                                                                            │
                                                                   ┌────────▼────────┐
                                                                   │ Netty Async RPC │
                                                                   │ → Broker Pull   │
                                                                   └────────┬────────┘
                                                                            │
                                                                   ┌────────▼────────┐
                                                                   │ PullCallback    │
                                                                   │ → 重新入队       │
                                                                   └─────────────────┘
```

## 6. DefaultMQPushConsumerImpl.pullMessage() 核心

### 6.1 方法概述

`DefaultMQPushConsumerImpl.pullMessage(PullRequest pullRequest)` 是整个消费链路中最核心的方法（约在源码行 246-499）。它包含：

1. **7 道流量控制门**
2. **偏移量搭车（Piggybacking）**
3. **PullCallback 异步回调构建**
4. **实际网络拉取调用**

### 6.2 流量控制详解

```java
// DefaultMQPushConsumerImpl.java (约 line 246)
public void pullMessage(final PullRequest pullRequest) {
    final ProcessQueue processQueue = pullRequest.getProcessQueue();

    // ========== 门控 1: ProcessQueue 已被丢弃 ==========
    if (processQueue.isDropped()) {
        log.info("the pull request is dropped after later, {}",
            pullRequest.toString());
        return;
    }

    // 更新最后拉取时间戳
    processQueue.setLastPullTimestamp(System.currentTimeMillis());

    try {
        // ========== 门控 2: 服务状态检查 ==========
        if (this.serviceState != ServiceState.RUNNING) {
            log.warn("pullMessage service is not running, {}",
                this.serviceState);
            // 延迟 3 秒后重试
            this.executePullRequestLater(pullRequest, PULL_TIME_DELAY_MILLS_WHEN_EXCEPTION);
            return;
        }

        // ========== 门控 3: 暂停状态 ==========
        if (this.isPause()) {
            log.info("consumer was paused, execute pull request later, {}",
                pullRequest.toString());
            // 延迟 1 秒后重试
            this.executePullRequestLater(pullRequest, PULL_TIME_DELAY_MILLS_WHEN_SUSPEND);
            return;
        }

        // ========== 门控 4: 消息数量流控 ==========
        long cachedMessageCount = processQueue.getMsgCount().get();
        if (cachedMessageCount > this.defaultMQPushConsumerImpl
                .getDefaultMQPushConsumer()
                .getPullThresholdForQueue()) {
            // 本地缓冲消息数超过阈值（默认 1000），延迟拉取
            this.executePullRequestLater(pullRequest,
                PULL_TIME_DELAY_MILLS_WHEN_FLOW_CONTROL);
            if ((queueFlowControlTimes++ % 1000) == 0) {
                log.warn(
                    "the cached message count exceeds the threshold {}, "
                    + "so do pull, {}, {}",
                    pullThresholdForQueue, pullRequest, cachedMessageCount);
            }
            return;
        }

        // ========== 门控 5: 消息大小流控 ==========
        long cachedMessageSizeInMiB = processQueue.getMsgSize().get() / (1024 * 1024);
        if (cachedMessageSizeInMiB > this.defaultMQPushConsumerImpl
                .getDefaultMQPushConsumer()
                .getPullThresholdSizeForQueue()) {
            // 本地缓冲消息大小超过阈值（默认 100MB），延迟拉取
            this.executePullRequestLater(pullRequest,
                PULL_TIME_DELAY_MILLS_WHEN_FLOW_CONTROL);
            if ((queueFlowControlTimes++ % 1000) == 0) {
                log.warn(
                    "the cached message size exceeds the threshold {}, "
                    + "so do pull, {}, {}",
                    pullThresholdSizeForQueue, pullRequest, cachedMessageSizeInMiB);
            }
            return;
        }

        if (!this.consumeOrderly) {
            // ========== 门控 6: 并发消费 - 最大跨度流控 ==========
            if (processQueue.getMaxSpan() > this.defaultMQPushConsumerImpl
                    .getDefaultMQPushConsumer()
                    .getConsumeConcurrentlyMaxSpan()) {
                // 消息跨度超过阈值（默认 2000），延迟拉取
                // MaxSpan = 最后一条消息偏移量 - 第一条消息偏移量
                // 说明消费严重不均，前面的消息还没消费完
                this.executePullRequestLater(pullRequest,
                    PULL_TIME_DELAY_MILLS_WHEN_FLOW_CONTROL);
                if ((queueFlowControlTimes++ % 1000) == 0) {
                    log.warn(
                        "the queue's messages, span too long, {} "
                        + "so do pull, {}, {}",
                        consumeConcurrentlyMaxSpan, pullRequest,
                        processQueue.getMaxSpan());
                }
                return;
            }
        } else {
            // ========== 门控 7: 顺序消费 - 锁检查 ==========
            if (processQueue.isLocked()) {
                if (!pullRequest.isLockedFirst()) {
                    // 首次拉取，重新计算偏移量
                    long offset = this.rebalanceImpl
                        .computePullFromWhere(pullRequest.getMessageQueue());
                    boolean brokerBusy = offset < pullRequest.getNextOffset();
                    log.info("the first time to pull message, so check, "
                        + "pull request: {}, {}",
                        pullRequest, brokerBusy ? "broker busy" : "broker ok");
                    pullRequest.setLockedFirst(true);
                    pullRequest.setNextOffset(offset);
                }
            } else {
                // ProcessQueue 未锁定，延迟 3 秒后重试
                this.executePullRequestLater(pullRequest,
                    PULL_TIME_DELAY_MILLS_WHEN_EXCEPTION);
                log.info("pull message later because not locked, {}",
                    pullRequest);
                return;
            }
        }

        // ========== 获取订阅信息 ==========
        final SubscriptionData subscriptionData = this.rebalanceImpl
            .getSubscriptionInner().get(pullRequest.getMessageQueue().getTopic());
        if (null == subscriptionData) {
            this.executePullRequestLater(pullRequest,
                PULL_TIME_DELAY_MILLS_WHEN_EXCEPTION);
            log.warn("find the consumer's subscription failed, {}",
                pullRequest);
            return;
        }

        // 消息数量限制
        final long beginTime = System.currentTimeMillis();
        int sysFlagPullDelay = PullSysFlag.buildSysFlag(
            false, // commitOffset
            true,  // suspend
            subscriptionData.isClassFilterMode(),
            true); // subscription
        long pullBoundary = 0;
        int maxNums = 0;
        if (this.consumeMessageService instanceof ConsumeMessageConcurrentlyService) {
            maxNums = this.consumeMessageService
                .getConsumeMessageQueue();
        } else if (this.consumeMessageService instanceof ConsumeMessageOrderlyService) {
            maxNums = this.consumeMessageService
                .getConsumeMessageQueue();
        }
        final int pullBatchSize = Math.min(
            this.defaultMQPushConsumer.getPullBatchSize(),
            maxNums);

        // ... 继续 PullCallback 构建（见下方）
    }
}
```

### 6.4 偏移量搭车（Piggybacking）

在发起 Pull 请求时，消费者会将内存中的消费偏移量附加在请求中，Broker 端据此更新持久化的偏移量，避免额外的 `UPDATE_CONSUMER_OFFSET` 请求：

```java
// DefaultMQPushConsumerImpl.pullMessage() 中
// ========== 偏移量搭车 ==========
long commitOffsetEnabled = false;
long commitOffsetValue = -1;
if (MessageModel.CLUSTERING == this.defaultMQPushConsumer.messageModel) {
    // 集群模式才支持偏移量搭车
    commitOffsetValue = this.offsetStore.readOffset(
        pullRequest.getMessageQueue(),
        OffsetStore.READ_FROM_MEMORY);
    if (commitOffsetValue > 0) {
        commitOffsetEnabled = true;
    }
}

// 构建系统标志位
int sysFlag = PullSysFlag.buildSysFlag(
    commitOffsetEnabled,   // bit 0: 是否携带 commitOffset
    true,                  // bit 1: 是否支持挂起（suspend）
    subscriptionData.isClassFilterMode(),  // bit 2: 类过滤模式
    true                   // bit 3: 是否携带订阅信息
);

String subExpression = subscriptionData.getSubString();
if (this.defaultMQPushConsumer.getMessageModel() == MessageModel.CLUSTERING) {
    subExpression = subscriptionData.getSubString();
}
```

`PullSysFlag` 的位定义：

```java
// PullSysFlag.java
public class PullSysFlag {
    private final static int FLAG_COMMIT_OFFSET = 0x1 << 0;   // bit 0
    private final static int FLAG_SUSPEND = 0x1 << 1;         // bit 1
    private final static int FLAG_SUBSCRIPTION = 0x1 << 2;    // bit 2
    private final static int FLAG_CLASS_FILTER = 0x1 << 3;    // bit 3

    public static int buildSysFlag(boolean commitOffset, boolean suspend,
            boolean subscription, boolean classFilter) {
        int flag = 0;
        if (commitOffset)    flag |= FLAG_COMMIT_OFFSET;
        if (suspend)         flag |= FLAG_SUSPEND;
        if (subscription)    flag |= FLAG_SUBSCRIPTION;
        if (classFilter)     flag |= FLAG_CLASS_FILTER;
        return flag;
    }

    public static boolean hasCommitOffsetFlag(int flag) {
        return (flag & FLAG_COMMIT_OFFSET) == FLAG_COMMIT_OFFSET;
    }

    public static boolean hasSuspendFlag(int flag) {
        return (flag & FLAG_SUSPEND) == FLAG_SUSPEND;
    }
    // ...
}
```

### 6.5 PullCallback 异步回调构建

PullCallback 是 Pull 请求的异步回调处理器，是消费链路的关键一环：

```java
// DefaultMQPushConsumerImpl.pullMessage() 续

PullCallback pullCallback = new PullCallback() {
    @Override
    public void onSuccess(PullResult pullResult) {
        if (pullResult != null) {
            // 处理拉取结果：解码、过滤
            pullResult = DefaultMQPushConsumerImpl.this.pullAPIWrapper
                .processPullResult(
                    pullRequest.getMessageQueue(), pullResult,
                    subscriptionData);

            switch (pullResult.getPullStatus()) {
                case FOUND:
                    // ========== 找到消息 ==========
                    long prevRequestOffset = pullRequest.getNextOffset();
                    pullRequest.setNextOffset(
                        pullResult.getNextBeginOffset());

                    long pullRT = System.currentTimeMillis() - beginTime;
                    // 更新统计
                    DefaultMQPushConsumerImpl.this.getConsumerStatsManager()
                        .incPullRT(pullRequest.getConsumerGroup(),
                            pullRequest.getMessageQueue().getTopic(), pullRT);

                    // 检查 ProcessQueue 是否已被丢弃
                    if (pullResult.getMsgFoundList() == null
                        || pullResult.getMsgFoundList().isEmpty()) {
                        // 没有有效消息（可能都被过滤了）
                        DefaultMQPushConsumerImpl.this.executePullRequestImmediately(
                            pullRequest);
                    } else {
                        // 将消息放入 ProcessQueue
                        boolean dispatchToConsume = processQueue.putMessage(
                            pullResult.getMsgFoundList());

                        // 更新统计
                        DefaultMQPushConsumerImpl.this.getConsumerStatsManager()
                            .incPullTPS(pullRequest.getConsumerGroup(),
                                pullRequest.getMessageQueue().getTopic(),
                                pullResult.getMsgFoundList().size());

                        // 提交消费请求
                        if (dispatchToConsume) {
                            DefaultMQPushConsumerImpl.this.consumeMessageService
                                .submitConsumeRequest(
                                    pullResult.getMsgFoundList(),
                                    processQueue,
                                    pullRequest.getMessageQueue(),
                                    dispatchToConsume);
                        }

                        // 重新入队继续拉取
                        if (DefaultMQPushConsumerImpl.this
                                .getDefaultMQPushConsumer().getPullInterval() > 0) {
                            // 有拉取间隔，延迟入队
                            DefaultMQPushConsumerImpl.this
                                .executePullRequestLater(pullRequest,
                                    DefaultMQPushConsumerImpl.this
                                        .getDefaultMQPushConsumer()
                                        .getPullInterval());
                        } else {
                            // 无间隔，立即入队
                            DefaultMQPushConsumerImpl.this
                                .executePullRequestImmediately(pullRequest);
                        }
                    }

                    if (pullResult.getNextBeginOffset() < prevRequestOffset
                        && pullRT > 0) {
                        log.warn(
                            "[BUG] pull message result maybe data wrong, "
                            + "nextBeginOffset={} prevRequestOffset={}",
                            pullResult.getNextBeginOffset(),
                            prevRequestOffset);
                    }
                    break;

                case NO_NEW_MSG:
                    // ========== 没有新消息 ==========
                    pullRequest.setNextOffset(
                        pullResult.getNextBeginOffset());
                    // 更新偏移量
                    DefaultMQPushConsumerImpl.this.correctTagsOffset(pullRequest);
                    // 立即重新拉取
                    DefaultMQPushConsumerImpl.this
                        .executePullRequestImmediately(pullRequest);
                    break;

                case NO_MATCHED_MSG:
                    // ========== 没有匹配的消息（被 tag 过滤） ==========
                    pullRequest.setNextOffset(
                        pullResult.getNextBeginOffset());
                    DefaultMQPushConsumerImpl.this.correctTagsOffset(pullRequest);
                    DefaultMQPushConsumerImpl.this
                        .executePullRequestImmediately(pullRequest);
                    break;

                case OFFSET_ILLEGAL:
                    // ========== 偏移量非法 ==========
                    log.warn(
                        "the pull request offset illegal, {} {}",
                        pullRequest, pullResult);
                    pullRequest.setNextOffset(
                        pullResult.getNextBeginOffset());
                    // 丢弃 ProcessQueue
                    pullRequest.getProcessQueue().setDropped(true);
                    // 持久化偏移量
                    DefaultMQPushConsumerImpl.this.offsetStore.updateOffset(
                        pullRequest.getMessageQueue(),
                        pullRequest.getNextOffset(), false);
                    DefaultMQPushConsumerImpl.this.offsetStore.persist(
                        pullRequest.getMessageQueue());
                    // 从 processQueueTable 移除，触发 Rebalance
                    DefaultMQPushConsumerImpl.this
                        .rebalanceImpl.removeProcessQueue(
                            pullRequest.getMessageQueue());
                    DefaultMQPushConsumerImpl.this.rebalanceImpl
                        .doRebalance(false);
                    break;

                default:
                    break;
            }
        }
    }

    @Override
    public void onException(Throwable e) {
        if (!pullRequest.getProcessQueue().isDropped()) {
            // 发生异常，延迟 3 秒后重试
            DefaultMQPushConsumerImpl.this.executePullRequestLater(
                pullRequest, PULL_TIME_DELAY_MILLS_WHEN_EXCEPTION);
        }
        log.warn("pull the message exception.", e);
    }
};
```

### 7.2 pullKernelImpl 核心方法

```java
// PullAPIWrapper.java
public PullResult pullKernelImpl(
        final MessageQueue mq,                    // 消息队列
        final String subExpression,               // 订阅表达式 (tag)
        final String expressionType,             // 表达式类型 (TAG/SQL92)
        final long subVersion,                    // 订阅版本
        final long offset,                        // 拉取偏移量
        final int maxNums,                        // 最大拉取数
        final int sysFlag,                        // 系统标志
        final long commitOffset,                  // 搭车的提交偏移量
        final long brokerSuspendMaxTimeMillis,    // Broker 最大挂起时间
        final long timeoutMillis,                 // 超时时间
        final CommunicationMode communicationMode,// 通信模式
        final PullCallback pullCallback           // 异步回调
) throws MQClientException, RemotingException, MQBrokerException,
         InterruptedException {

    // 1. 查找 Broker 地址
    FindBrokerResult findBrokerResult =
        this.mQClientFactory.findBrokerAddressInSubscribe(
            mq.getBrokerName(),
            this.recalculatePullFromWhichNode(mq),  // 推荐 Broker ID
            false);

    if (null == findBrokerResult) {
        // 没找到 Broker，重新从 NameServer 更新路由
        this.mQClientFactory.updateTopicRouteInfoFromNameServer(mq.getTopic());
        findBrokerResult = this.mQClientFactory.findBrokerAddressInSubscribe(
            mq.getBrokerName(),
            this.recalculatePullFromWhichNode(mq), false);
    }

    if (findBrokerResult != null) {
        // 2. 构建请求头
        PullMessageRequestHeader requestHeader = new PullMessageRequestHeader();
        requestHeader.setConsumerGroup(this.consumerGroup);
        requestHeader.setTopic(mq.getTopic());
        requestHeader.setQueueId(mq.getQueueId());
        requestHeader.setQueueOffset(offset);
        requestHeader.setMaxMsgNums(maxNums);
        requestHeader.setSysFlag(sysFlag);
        requestHeader.setCommitOffset(commitOffset);
        requestHeader.setSuspendTimeoutMillis(brokerSuspendMaxTimeMillis);
        requestHeader.setSubscription(subExpression);
        requestHeader.setSubVersion(subVersion);
        requestHeader.setExpressionType(expressionType);

        // 如果是类过滤模式，设置用于过滤的消费者组
        if (PullSysFlag.hasClassFilterFlag(sysFlag)) {
            requestHeader.setConsumerGroup(
                this.mQClientFactory.getClientId() + "_" + this.consumerGroup);
        }

        String brokerAddr = findBrokerResult.getBrokerAddr();
        if (PullSysFlag.hasClassFilterFlag(sysFlag)) {
            brokerAddr = computePullFromWhichFilterServerToPull(
                mq, findBrokerResult);
        }

        // 3. 根据通信模式发起请求
        PullResult pullResult = this.mQClientFactory.getMQClientAPIImpl()
            .pullMessage(
                brokerAddr,
                requestHeader,
                timeoutMillis,
                communicationMode,
                pullCallback);

        // 同步模式直接返回结果，异步模式返回 null
        return pullResult;
    }

    throw new MQClientException(
        "The broker[" + mq.getBrokerName() + "] not exist", null);
}
```

```java
// PullAPIWrapper.java
public PullResult processPullResult(final MessageQueue mq,
        final PullResult pullResult, final SubscriptionData subscriptionData) {

    // 更新推荐 Broker
    if (pullResult != null && pullResult.getPullStatus() != null) {
        PullStatus pullStatus = pullResult.getPullStatus();
        if (pullStatus == PullStatus.FOUND
            || pullStatus == PullStatus.OFFSET_MOVED
            || pullStatus == PullStatus.NO_MATCHED_MSG) {
            // Broker 返回了建议的 Broker ID
            this.updatePullFromWhichNode(mq, pullResult.getSuggestWhichBrokerId());
        }

        // 如果找到了消息
        if (PullStatus.FOUND == pullStatus) {
            // 解码消息
            ByteBuffer byteBuffer = ByteBuffer.wrap(pullResult.getBinaryPayload());
            List<MessageExt> msgList = MessageDecoder.decodes(
                byteBuffer);

            // 客户端 TAG 过滤
            List<MessageExt> msgListFilterAgain = new ArrayList<>();
            for (MessageExt msg : msgList) {
                // 消息属性设置
                MessageAccessor.setSubstringFromMessage(msg,
                    subscriptionData.getSubString());
                MessageAccessor.putProperty(msg,
                    MessageConst.PROPERTY_MSG_REGION,
                    subscriptionData.getMsgRegion());

                // TAG 过滤
                if (subscriptionData.isTagsType() && !subscriptionData
                        .getTagsSet().isEmpty()
                    && !subscriptionData.getTagsSet()
                        .contains(msg.getTags())) {
                    // TAG 不匹配，跳过
                    continue;
                }

                msgListFilterAgain.add(msg);
            }

            // 执行过滤钩子
            if (this.hasHook()) {
                for (FilterMessageHook hook : filterMessageHookList) {
                    try {
                        hook.filterMessage(filterContext, msgListFilterAgain);
                    } catch (Throwable e) {
                        log.error("execute hook error. hookName={}",
                            hook.getHookName(), e);
                    }
                }
            }

            // 更新拉取结果
            pullResult.setMsgFoundList(msgListFilterAgain);
        }

        // 清空二进制负载
        pullResult.setBinaryPayload(null);
    }

    return pullResult;
}
```

```java
                    } else if (responseFuture.isTimeout()) {

                    } else {
                        pullCallback.onException(
                            new MQClientExceptionException(
                                "unknown reason. addr=" + addr, null));

                }
            }
        });
```

### 8.3 submitConsumeRequest 提交消费请求

当 PullCallback 收到 FOUND 状态的消息后，调用 `submitConsumeRequest` 提交消费：

```java
// ConsumeMessageConcurrentlyService.java
@Override
public void submitConsumeRequest(
        final List<MessageExt> msgs,
        final ProcessQueue processQueue,
        final MessageQueue messageQueue,
        final boolean dispatchToConsume) {

    // 默认 consumeBatchSize = 1，即每次只消费 1 条消息
    final int consumeBatchSize = this.defaultMQPushConsumer
        .getConsumeMessageBatchMaxSize();

    if (msgs.size() <= consumeBatchSize) {
        // 消息数不超过批量大小，直接提交单个消费请求
        ConsumeRequest consumeRequest = new ConsumeRequest(
            msgs, processQueue, messageQueue);
        try {
            this.consumeExecutor.submit(consumeRequest);
        } catch (RejectedExecutionException e) {
            // 线程池拒绝，延迟提交
            this.submitConsumeRequestLater(consumeRequest);
        }
    } else {
        // 消息数超过批量大小，拆分成多个批次
        for (int total = 0; total < msgs.size(); ) {
            List<MessageExt> msgThis = new ArrayList<>(
                consumeBatchSize);
            for (int i = 0; i < consumeBatchSize; i++, total++) {
                if (total < msgs.size()) {
                    msgThis.add(msgs.get(total));
                } else {
                    break;
                }
            }

            ConsumeRequest consumeRequest = new ConsumeRequest(
                msgThis, processQueue, messageQueue);
            try {
                this.consumeExecutor.submit(consumeRequest);
            } catch (RejectedExecutionException e) {
                for (; total < msgs.size(); total++) {
                    msgThis.add(msgs.get(total));
                }
                this.submitConsumeRequestLater(consumeRequest);
            }
        }
    }
}
```

### 8.4 ConsumeRequest 消费任务

`ConsumeRequest` 是一个 `Runnable`，在消费线程池中执行实际的消息消费逻辑：

```java
// ConsumeMessageConcurrentlyService.java
class ConsumeRequest implements Runnable {
    private final List<MessageExt> msgs;
    private final ProcessQueue processQueue;
    private final MessageQueue messageQueue;

    public ConsumeRequest(List<MessageExt> msgs, ProcessQueue processQueue,
            MessageQueue messageQueue) {
        this.msgs = msgs;
        this.processQueue = processQueue;
        this.messageQueue = messageQueue;
    }

    @Override
    public void run() {
        // 1. 检查 ProcessQueue 是否已丢弃
        if (this.processQueue.isDropped()) {
            log.info("the message queue not be able to consume, "
                + "because it's dropped. group={} {}", ConsumeMessageConcurrentlyService
                .this.consumerGroup, this.messageQueue);
            return;
        }

        // 获取消息上下文
        MessageExtConsumeContext context = new MessageExtConsumeContext();
        context.setConsumerGroup(consumerGroup);
        context.setMq(messageQueue);
        context.setMsgs(msgs);
        context.setSuccess(false);
        context.setNextOffset(-1L);

        // 2. 设置消费开始时间
        long beginTimestamp = System.currentTimeMillis();
        ConsumeMessageConcurrentlyService.this.defaultMQPushConsumerImpl
            .resetRetryAndNamespace(msgs, this.messageQueue.getTopic());

        // 3. 执行消费前置钩子
        if (!ConsumeMessageConcurrentlyService.this.defaultMQPushConsumerImpl
                .getMessageListenerInner().equals(null)) {
            // ...
        }

        // 4. 调用用户消息监听器
        ConsumeMessageConcurrentlyService.this.defaultMQPushConsumerImpl
            .executeHookBefore(context);
        ConsumeMessageConcurrentlyService.this.consumeHook
            .consumeMessageBefore(context);

        long startTimestamp = System.currentTimeMillis();
        ConsumeReturnType returnType = ConsumeReturnType.SUCCESS;
        ConsumeStatus status = null;
        try {
            // 调用用户的 MessageListenerConcurrently.consumeMessage()
            status = ConsumeMessageConcurrentlyService.this.messageListener
                .consumeMessage(
                    Collections.unmodifiableList(msgs), context);
        } catch (Throwable e) {
            log.warn("consumeMessage exception: {} Group: {} Msgs: {}",
                ConsumeMessageConcurrentlyService.this.consumerGroup,
                msgs, e);
            returnType = ConsumeReturnType.EXCEPTION;
        }

        // 5. 计算消费耗时
        long consumeRT = System.currentTimeMillis() - startTimestamp;
        if (null == status) {
            // 发生异常，标记为 RECONSUME_LATER
            status = ConsumeStatus.RECONSUME_LATER;
            returnType = ConsumeReturnType.RT_EXCEPTION;
        }

        // 6. 执行消费后置钩子
        context.setStatus(status);
        context.setSuccess(
            status == ConsumeStatus.CONSUME_SUCCESS);
        context.setRT(consumeRT);
        ConsumeMessageConcurrentlyService.this.defaultMQPushConsumerImpl
            .executeHookAfter(context);
        ConsumeMessageConcurrentlyService.this.consumeHook
            .consumeMessageAfter(context);

        // 7. 处理消费结果
        if (!processQueue.isDropped()) {
            ConsumeMessageConcurrentlyService.this.processConsumeResult(
                status, this, consumeRT);
        }
    }

    public List<MessageExt> getMsgs() {
        return msgs;
    }

    public MessageQueue getMessageQueue() {
        return messageQueue;
    }
}
```

## 9. processConsumeResult 结果处理与重试

### 9.1 processConsumeResult 方法

这是消费结果处理的核心方法，决定了消息是否需要重试、如何更新偏移量：

```java
// ConsumeMessageConcurrentlyService.java
public void processConsumeResult(
        final ConsumeStatus status,
        final ConsumeRequest consumeRequest,
        final boolean consumeSuccess,
        final boolean dispatchToConsume,
        final long consumeRT) {

    // 省略部分代码，核心逻辑如下：

    // 获取消费结果中的消息和 ProcessQueue
    List<MessageExt> msgs = consumeRequest.getMsgs();
    ProcessQueue processQueue = consumeRequest.getProcessQueue();
    MessageQueue messageQueue = consumeRequest.getMessageQueue();

    // 确定消费结果
    int ackIndex = -1;
    switch (status) {
        case CONSUME_SUCCESS:
            // 消费成功
            if (consumeSuccess) {
                ackIndex = msgs.size();  // 全部确认
            } else {
                // 部分成功（batch消费时可能部分失败）
                ackIndex = consumeRequest.getAckIndex();
            }
            break;
        case RECONSUME_LATER:
            // 消费失败，需要重试
            ackIndex = -1;  // 全部不确认（全部重试）
            break;
        default:
            break;
    }

    // 根据消息模型处理
    switch (this.defaultMQPushConsumerImpl.messageModel) {
        case BROADCASTING:
            // 广播模式：不重试，只记录日志
            for (int i = ackIndex + 1; i < msgs.size(); i++) {
                log.warn("BROADCASTING, the message consume failed, "
                    + "drop it, {}", msgs.get(i));
            }
            break;
        case CLUSTERING:
            // 集群模式：消费失败的消息发回到 Broker 的重试队列
            List<MessageExt> failedMsgs = new ArrayList<>();
            for (int i = ackIndex + 1; i < msgs.size(); i++) {
                log.warn("CLUSTERING, the message consume failed, "
                    + "retry it later, index={}, {}", i, msgs.get(i));
                failedMsgs.add(msgs.get(i));
            }

            // 发送重试消息到 Broker
            if (!failedMsgs.isEmpty()) {
                this.sendMessageBack(failedMsgs, messageQueue);
            }
            break;
        default:
            break;
    }

    // 从 ProcessQueue 移除已消费的消息
    long offset = processQueue.removeMessage(msgs);

    // 更新偏移量
    if (offset >= 0 && !processQueue.isDropped()) {
        this.defaultMQPushConsumerImpl.getOffsetStore().updateOffset(
            messageQueue, offset, true);
    }
}
```

## 10. ProcessQueue 本地消息缓冲

### 10.1 ProcessQueue 数据结构

`ProcessQueue` 是消费者端的消息缓冲区，与每个 `MessageQueue` 一一对应：

```java
// ProcessQueue.java
public class ProcessQueue {
    // 消息树：按 offset 排序的 TreeMap
    private final TreeMap<Long, MessageExt> msgTreeMap = new TreeMap<>();

    // 读写锁：保护 msgTreeMap
    private final ReadWriteLock lockTreeMap = new ReentrantReadWriteLock();

    // 消息数量（原子）
    private final AtomicLong msgCount = new AtomicLong();

    // 消息总大小（字节）
    private final AtomicLong msgSize = new AtomicLong();

    // 队列最大 offset
    private final AtomicLong queueOffsetMax = new AtomicLong(Long.MAX_VALUE);

    // 是否已丢弃
    private volatile boolean dropped = false;

    // 最后拉取时间
    private volatile long lastPullTimestamp = System.currentTimeMillis();

    // 最后消费时间
    private volatile long lastConsumeTimestamp = System.currentTimeMillis();

    // 顺序消费相关
    private final Lock consumeLock = new ReentrantLock();

    private final TreeMap<Long, MessageExt> consumingMsgOrderlyTreeMap =
        new TreeMap<>();

    // 顺序消费锁

    private volatile long lastLockTimestamp = System.currentTimeMillis();
    private volatile long tryUnlockTimes = 0;
    private volatile boolean lockExpired = false;
```

### 10.2 putMessage 放入消息

```java
// ProcessQueue.java
public boolean putMessage(final List<MessageExt> msgs) {
    boolean dispatchToConsume = false;
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            int validMsgCnt = 0;
            for (int i = 0; i < msgs.size(); i++) {
                MessageExt msg = msgs.get(i);
                // 以 queueOffset 为 key 放入 TreeMap
                MessageExt old = msgTreeMap.put(msg.getQueueOffset(), msg);
                if (old != null) {
                    // 重复消息，跳过
                    log.warn("We had received this message, {}", msg);
                    continue;
                }

                // 更新计数
                validMsgCnt++;
                msgSize.addAndGet(msg.getBody() != null
                    ? msg.getBody().length : 0);

                // 更新最大 offset
                queueOffsetMax.set(msg.getQueueOffset());
            }

            // 更新消息数            msgCount.addAndGet(validMsgCnt);

            if (!msgTreeMap.isEmpty() && !this.consumingMsgOrderlyTreeMap.isEmpty()) {
                // 顺序消费模式下检查是否有正在消费的消息
                dispatchToConsume = true;
            }
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("putMessage exception", e);
    }

    return dispatchToConsume;
}
```

### 10.3 removeMessage 移除已消费消息

```java
// ProcessQueue.java
public long removeMessage(final List<MessageExt> msgs) {
    long result = -1;
    final long now = System.currentTimeMillis();
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            long lastOffset = -1;
            boolean removed = false;
            for (MessageExt msg : msgs) {
                // 从 TreeMap 中移除
                MessageExt prev = msgTreeMap.remove(msg.getQueueOffset());
                if (prev != null) {
                    removed = true;
                    // 减少计数
                    msgSize.addAndGet(0 - (msg.getBody() != null
                        ? msg.getBody().length : 0));
                    lastOffset = msg.getQueueOffset();
                }
            }

            if (removed) {
                msgCount.addAndGet(-msgs.size());
                if (!msgTreeMap.isEmpty()) {
                    // 返回当前最小的 offset（下一条待消费的 offset）
                    result = msgTreeMap.firstKey();
                } else {
                    // TreeMap 为空，返回最大 offset + 1
                    result = queueOffsetMax.get() + 1;
                }
            }
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (Throwable t) {
        log.error("removeMessage exception", t);
    }

    return result;
}
```

**返回值含义**：
- 返回值是当前 ProcessQueue 中下一条待消费消息的 offset
- 如果 ProcessQueue 中还有消息，返回 `msgTreeMap.firstKey()`（最小 offset）
- 如果 ProcessQueue 已空，返回 `queueOffsetMax + 1`（下一条新消息的 offset）

### 10.4 getMaxSpan 最大跨度

```java
// ProcessQueue.java
public long getMaxSpan() {
    try {
        this.lockTreeMap.readLock().lockInterruptibly();
        try {
            if (!msgTreeMap.isEmpty()) {
                // 最大跨度 = 最后一条消息 offset - 第一条消息 offset
                return msgTreeMap.lastKey() - msgTreeMap.firstKey();
            }
        } finally {
            this.lockTreeMap.readLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("getMaxSpan exception", e);
    }

    return 0;
}
```

MaxSpan 表示 ProcessQueue 中消息的偏移量跨度。如果跨度过大（默认 > 2000），说明前面的消息消费很慢而后面不断有新消息拉入，此时需要暂停拉取。

### 10.5 ProcessQueue 顺序消费方法

对于顺序消费，ProcessQueue 提供了额外的方法：

```java
// ProcessQueue.java - 顺序消费专用

/**
 * 获取消息但不移除，移到 consumingMsgOrderlyTreeMap
 */
public List<MessageExt> takeMessages(final ConsumeMessageOrderlyService service,
        final int batchSize) {
    List<MessageExt> result = new ArrayList<>(batchSize);
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            if (!this.msgTreeMap.isEmpty()) {
                for (int i = 0; i < batchSize && !this.msgTreeMap.isEmpty(); i++) {
                    Map.Entry<Long, MessageExt> entry = this.msgTreeMap.pollFirstEntry();
                    if (entry != null) {
                        result.add(entry.getValue());
                        // 移到正在消费的 map
                        consumingMsgOrderlyTreeMap.put(
                            entry.getKey(), entry.getValue());
                    }
                }
            }
            if (!result.isEmpty()) {
                // 更新最后消费时间
                lastConsumeTimestamp = System.currentTimeMillis();
            }
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("takeMessages exception", e);
    }
    return result;
}

/**
 * 提交（确认消费）
 */
public long commit() {
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            // 获取正在消费的消息
            Long offset = this.consumingMsgOrderlyTreeMap.lastKey();
            // 清空正在消费的 map
            msgCount.addAndGet(-this.consumingMsgOrderlyTreeMap.size());
            for (MessageExt msg : this.consumingMsgOrderlyTreeMap.values()) {
                msgSize.addAndGet(0 - (msg.getBody() != null
                    ? msg.getBody().length : 0));
            }
            this.consumingMsgOrderlyTreeMap.clear();

            // 返回下一个 offset
            if (!msgTreeMap.isEmpty()) {
                return msgTreeMap.firstKey();
            }
            return offset + 1;
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("commit exception", e);
    }
    return -1;
}

/**
 * 回滚（放回 msgTreeMap）
 */
public void rollback() {
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            // 将正在消费的消息放回 msgTreeMap
            for (MessageExt msg : this.consumingMsgOrderlyTreeMap.values()) {
                this.msgTreeMap.put(msg.getQueueOffset(), msg);
            }
            this.consumingMsgOrderlyTreeMap.clear();
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("rollback exception", e);
    }
}

/**
 * 重新消费（放回 msgTreeMap 前面）
 */
public void makeMessageToConsumeAgain(List<MessageExt> msgs) {
    try {
        this.lockTreeMap.writeLock().lockInterruptibly();
        try {
            for (MessageExt msg : msgs) {
                // 从正在消费的 map 移除
                this.consumingMsgOrderlyTreeMap.remove(msg.getQueueOffset());
                // 放回 msgTreeMap
                this.msgTreeMap.put(msg.getQueueOffset(), msg);
            }
        } finally {
            this.lockTreeMap.writeLock().unlock();
        }
    } catch (InterruptedException e) {
        log.error("makeMessageToConsumeAgain exception", e);
    }
}
```

### 11.2 RemoteBrokerOffsetStore（集群模式）

集群模式下使用 `RemoteBrokerOffsetStore`，偏移量存储在 Broker 端：

```java
// RemoteBrokerOffsetStore.java
public class RemoteBrokerOffsetStore implements OffsetStore {
    private final MQClientInstance mQClientFactory;
    private final String groupName;
    // 内存中的偏移量表
    private ConcurrentMap<MessageQueue, AtomicLong> offsetTable =
        new ConcurrentHashMap<>();

    @Override
    public void load() {
        // 集群模式下不需要本地加载，偏移量从 Broker 获取
    }

    @Override
    public void updateOffset(MessageQueue mq, long offset, boolean increaseOnly) {
        if (mq != null) {
            AtomicLong offsetOld = this.offsetTable.get(mq);
            if (null == offsetOld) {
                offsetOld = this.offsetTable.putIfAbsent(mq, new AtomicLong(offset));
            }

            if (null != offsetOld) {
                if (increaseOnly) {
                    // 只增不减：取较大值
                    MixAll.compareAndIncreaseOnly(offsetOld, offset);
                } else {
                    offsetOld.set(offset);
                }
            }
        }
    }

    @Override
    public long readOffset(final MessageQueue mq, final ReadType readType) {
        if (mq != null) {
            switch (readType) {
                case READ_FROM_MEMORY: {
                    // 从内存读取
                    AtomicLong offset = this.offsetTable.get(mq);
                    if (offset != null) {
                        return offset.get();
                    }
                    break;
                }
                case READ_FROM_STORE: {
                    // 从 Broker 读取
                    try {
                        long brokerOffset = this.fetchConsumeOffsetFromBroker(mq);
                        if (brokerOffset != -1) {
                            // 更新内存
                            this.updateOffset(mq, brokerOffset, false);
                            return brokerOffset;
                        }
                    } catch (Exception e) {
                        log.error("readOffset READ_FROM_STORE exception", e);
                    }
                    break;
                }
                case READ_FROM_MEMORY_THEN_STORE: {
                    // 先内存后 Broker
                    AtomicLong offset = this.offsetTable.get(mq);
                    if (offset != null) {
                        return offset.get();
                    } else {
                        try {
                            long brokerOffset = this.fetchConsumeOffsetFromBroker(mq);
                            if (brokerOffset != -1) {
                                this.updateOffset(mq, brokerOffset, false);
                                return brokerOffset;
                            }
                        } catch (Exception e) {
                            log.error("readOffset READ_FROM_MEMORY_THEN_STORE", e);
                        }
                    }
                    break;
                }
                default:
                    break;
            }
        }

        return -1;
    }
}
```

### 11.3 persistAll 持久化到Broker

```java
// RemoteBrokerOffsetStore.java
@Override
public void persistAll(Set<MessageQueue> mqs) {
    if (null == mqs || mqs.isEmpty()) {
        return;
    }

    // 遍历所有需要持久化的 MessageQueue
    for (Map.Entry<MessageQueue, AtomicLong> entry : this.offsetTable.entrySet()) {
        MessageQueue mq = entry.getKey();
        if (!mqs.contains(mq)) {
            continue;
        }

        AtomicLong offset = entry.getValue();
        if (offset == null) {
            continue;
        }

        try {
            // 向 Broker 发送 UPDATE_CONSUMER_OFFSET 请求
            this.updateAndFetchConsumeOffsetToBroker(
                mq, offset.get(), true);
        } catch (Exception e) {
            log.error("persistAll consumer offset exception", e);
        }
    }
}

@Override

    FindBrokerResult findBrokerResult = this.mQClientFactory

        findBrokerResult = this.mQClientFactory.findBrokerAddressInSubscribe(

        requestHeader.setQueueId(mq.getQueueId());
```

## 12. Broker 端 PullMessageProcessor

### 12.1 processRequest 入口

Broker 端处理 Pull 请求的核心处理器是 `PullMessageProcessor`：

```java
// PullMessageProcessor.java
@Override
public RemotingCommand processRequest(final Channel channel,
        RemotingCommand request) throws RemotingException {

    return processRequest(channel, request, true);
}

private RemotingCommand processRequest(final Channel channel,
        RemotingCommand request, boolean brokerAllowSuspend)
        throws RemotingException {

    final long beginTimeMills = this.brokerController.getMessageStore().now();
    RemotingCommand response = RemotingCommand.createResponseCommand(
        PullMessageResponseHeader.class);
    final PullMessageResponseHeader responseHeader =
        (PullMessageResponseHeader) response.readCustomHeader();
    final PullMessageRequestHeader requestHeader =
        (PullMessageRequestHeader) request.decodeCommandCustomHeader(
            PullMessageRequestHeader.class);

    // 打印拉取请求日志
    if (log.isDebugEnabled()) {
        log.debug("receive PullMessage request command, {}", requestHeader);
    }

    response.setOpaque(request.getOpaque());
    response.addExtField("topic", requestHeader.getTopic());
    response.addExtField("queue", String.valueOf(requestHeader.getQueueId()));

    // ========== 1. 权限检查 ==========
    if (!PermName.isReadable(this.brokerController.getBrokerConfig()
            .getBrokerPermission())) {
        response.setCode(ResponseCode.NO_PERMISSION);
        response.setRemark(String.format("the broker[%s] consuming message is forbidden",
            this.brokerController.getBrokerConfig().getBrokerIP1()));
        return response;
    }

    // ========== 2. 消费组检查 ==========
    if (!this.brokerController.getConsumerManager()
            .containsGroup(requestHeader.getConsumerGroup())) {
        // 消费者组不存在
        response.setCode(ResponseCode.SUBSCRIPTION_GROUP_NOT_EXIST);
        response.setRemark(String.format("group[%s] is not online",
            requestHeader.getConsumerGroup()));
        return response;
    }

    // ========== 3. 订阅信息检查 ==========
    // 检查消费者组是否订阅了该 Topic
    SubscriptionData subscriptionData = null;
    if (requestHeader.getSubscription() != null
            && !requestHeader.getSubscription().isEmpty()) {
        // 从消费者管理器获取订阅数据
        ConsumerGroupInfo consumerGroupInfo =
            this.brokerController.getConsumerManager()
                .getConsumerGroupInfo(requestHeader.getConsumerGroup());
        if (consumerGroupInfo != null) {
            subscriptionData = consumerGroupInfo.findSubscriptionData(
                requestHeader.getTopic(), requestHeader.getSubscription());
        }
    }

    // 如果没有订阅数据，使用请求头中的信息构建
    if (null == subscriptionData) {
        // 构建 SubscriptionData
        if (requestHeader.getSubscription() == null
            && !PullSysFlag.hasSubscriptionFlag(requestHeader.getSysFlag())) {
            response.setCode(ResponseCode.SUBSCRIPTION_NOT_LATEST);
            response.setRemark("subscription data not exist");
            return response;
        }

        // 从请求头构建订阅数据
        subscriptionData = new SubscriptionData();
        subscriptionData.setTopic(requestHeader.getTopic());
        subscriptionData.setSubString(requestHeader.getSubscription());
        subscriptionData.setExpressionType(requestHeader.getExpressionType());
    }

    // ========== 4. 构建消息过滤器 ==========
    MessageFilter messageFilter;
    if (subscriptionData.getSubString() == null
            || subscriptionData.getSubString().equals(SubscriptionData.SUB_ALL)
            || subscriptionData.getSubString().isEmpty()) {
        // 订阅全部消息
        messageFilter = null;
    } else {
        // 构建 TAG 过滤器
        messageFilter = new ExpressionMessageFilter(
            subscriptionData, this.brokerController.getSubscriptionGroupManager()
                .findSubscriptionGroupConfig(requestHeader.getConsumerGroup()));
    }

    // ========== 5. 消息存储查询 ==========
    final boolean hasCommitOffsetFlag = PullSysFlag
        .hasCommitOffsetFlag(requestHeader.getSysFlag());
    final boolean suspend = PullSysFlag.hasSuspendFlag(requestHeader.getSysFlag());
    final long suspendTimeoutMillisLong = requestHeader.getSuspendTimeoutMillis();

    // 调用消息存储异步获取消息
    final GetMessageResult getMessageResult = this.brokerController
        .getMessageStore().getMessageAsync(

            requestHeader.getQueueOffset(),     // 起始 offset
            requestHeader.getMaxMsgNums(),      // 最大消息数
            messageFilter,                      // 消息过滤器
            commitOffsetEnable                  // 是否提交 offset

        try {

                result, request, requestHeader, channel, subscriptionData,

                suspendTimeoutMillisLong, hasCommitOffsetFlag,
```

```java
        long offset, int maxMsgNums, MessageFilter messageFilter) {

    long beginTime = this.getSystemClock().now();
    GetMessageStatus status = GetMessageStatus.NO_MESSAGE_IN_QUEUE;
    long nextBeginOffset = offset;
    long minOffset = 0;
    long maxOffset = 0;

        maxOffset = consumeQueue.getMaxOffsetInQueue();

        // 检查 offset 是否合法
        if (offset < minOffset) {
            status = GetMessageStatus.OFFSET_TOO_SMALL;
            nextBeginOffset = minOffset;
        } else if (offset == maxOffset) {
            status = GetMessageStatus.OFFSET_OVERFLOW_ONE;
            nextBeginOffset = offset;
        } else if (offset > maxOffset) {
            status = GetMessageStatus.OFFSET_OVERFLOW_BADLY;
            nextBeginOffset = maxOffset;
        } else {
            // offset 合法，从 ConsumeQueue 中读取消息
            SelectMappedBufferResult bufferResult = consumeQueue.getIndexBuffer(
                offset);
            if (bufferResult != null) {
                int maxPullSize = ... ;
                int maxFilterMessageCount = ...;

                try {
                    List<SelectMappedBufferResult> buffers = new ArrayList<>();
                    long nextOffset = offset;
                    int i = 0;

                    // 遍历 ConsumeQueue 条目
                    while (i < maxMsgNums && i < maxFilterMessageCount) {
                        // 读取 ConsumeQueue 条目：physOffset, physSize, tagCode
                        long physOffset = ...;
                        int physSize = ...;
                        long tagsCode = ...;

                        // TAG 过滤
                        if (messageFilter != null
                            && !messageFilter.isMatchedByConsumeQueue(
                                tagsCode, ...)) {
                            nextOffset++;
                            continue;
                        }

                        // 从 CommitLog 读取消息
                        SelectMappedBufferResult selectResult =
                            this.commitLog.getMessage(physOffset, physSize);
                        if (selectResult != null) {
                            // TAG 过滤（消息体级别）
                            if (messageFilter != null
                                && !messageFilter.isMatchedByCommitLog(
                                    selectResult.getByteBuffer(), ...)) {
                                nextOffset++;
                                selectResult.release();
                                continue;
                            }

                            buffers.add(selectResult);
                            getResult.addMsg(selectResult);
                            status = GetMessageStatus.FOUND;
                            i++;
                            nextOffset++;
                        }
                    }

                    nextBeginOffset = nextOffset;
                } finally {
                    bufferResult.release();
                }

                // 如果没找到消息
                if (GetMessageStatus.FOUND != status) {
                    // 设置建议的下一个 offset
                    if (nextBeginOffset == offset) {
                        nextBeginOffset = nextOffset;
                    }
                }
            } else {
                // ConsumeQueue 读取失败
                status = GetMessageStatus.OFFSET_FOUND_NULL;
                nextBeginOffset = consumeQueue.rollNextFile(offset);
            }
        }
    } else {
        status = GetMessageStatus.NO_MATCHED_LOGIC_QUEUE;
    }

    // 设置结果
    getResult.setStatus(status);
    getResult.setNextBeginOffset(nextBeginOffset);
    getResult.setMaxOffset(maxOffset);
    getResult.setMinOffset(minOffset);

    return getResult;
}
```

### 13.1 DefaultPullMessageResultHandler.handle

`DefaultPullMessageResultHandler` 是 Broker 端处理拉取结果的处理器：

```java
// DefaultPullMessageResultHandler.java
public RemotingCommand handle(GetMessageResult getMessageResult,
        RemotingCommand request, PullMessageRequestHeader requestHeader,
        Channel channel, SubscriptionData subscriptionData,
        MessageFilter messageFilter, boolean brokerAllowSuspend,
        boolean suspend, long suspendTimeoutMillisLong,
        boolean hasCommitOffsetFlag, long beginTimeMills) {

    RemotingCommand response = RemotingCommand.createResponseCommand(
        PullMessageResponseHeader.class);
    final PullMessageResponseHeader responseHeader =
        (PullMessageResponseHeader) response.readCustomHeader();

    response.setOpaque(request.getOpaque());
    response.addExtField("topic", requestHeader.getTopic());
    response.addExtField("queue", String.valueOf(requestHeader.getQueueId()));

    switch (getMessageResult.getStatus()) {
        case FOUND:
            // ========== 找到消息 ==========
            response.setCode(ResponseCode.SUCCESS);
            break;

        case NO_MATCHED_MESSAGE:
            // ========== 没有匹配的消息 ==========
            response.setCode(ResponseCode.PULL_RETRY_IMMEDIATELY);
            break;

        case NO_MESSAGE_IN_QUEUE:
            // ========== 队列为空 ==========
            if (0 != requestHeader.getQueueOffset()) {
                response.setCode(ResponseCode.PULL_OFFSET_MOVED);
            } else {
                response.setCode(ResponseCode.PULL_NOT_FOUND);
            }
            break;

        case MESSAGE_REQURING_NOT_CHANGED:
            response.setCode(ResponseCode.PULL_NOT_FOUND);
            break;

        case OFFSET_FOUND_NULL:
        case OFFSET_OVERFLOW_ONE:
            response.setCode(ResponseCode.PULL_NOT_FOUND);
            break;

        case OFFSET_OVERFLOW_BADLY:
            response.setCode(ResponseCode.PULL_OFFSET_MOVED);
            break;

        case OFFSET_TOO_SMALL:
            response.setCode(ResponseCode.PULL_OFFSET_MOVED);
            break;

        default:
            response.setCode(ResponseCode.SYSTEM_ERROR);
            break;
    }

    // 设置响应头
    responseHeader.setNextBeginOffset(getMessageResult.getNextBeginOffset());
    responseHeader.setMinOffset(getMessageResult.getMinOffset());
    responseHeader.setMaxOffset(getMessageResult.getMaxOffset());
    responseHeader.setSuggestWhichBrokerId(subscriptionGroupConfig != null
        ? subscriptionGroupConfig.getBrokerId() : MixAll.MASTER_ID);

    // ========== 长轮询挂起逻辑 ==========
    if (ResponseCode.PULL_NOT_FOUND == response.getCode()) {
        // 没有找到消息
        if (brokerAllowSuspend && hasSuspendFlag(requestHeader.getSysFlag())) {
            // 允许挂起且消费者支持挂起
            // 构建 PullRequest（Broker端的挂起请求）
            PullRequest pullRequest = new PullRequest(
                request,                          // 原始请求
                channel,                          // 通道
                suspendTimeoutMillisLong,         // 挂起超时时间
                request,                          // 请求命令
                requestHeader.getConsumerGroup(), // 消费组
                requestHeader.getTopic(),         // Topic
                requestHeader.getQueueId(),       // 队列 ID
                requestHeader.getQueueOffset(),   // 偏移量
                subscriptionData,                 // 订阅数据
                messageFilter                     // 消息过滤器
            );

            // 挂起到 PullRequestHoldService
            this.brokerController.getPullRequestHoldService()
                .suspendPullRequest(
                    requestHeader.getTopic() + "@"
                    + requestHeader.getQueueId(),
                    pullRequest);

            // 返回 null，表示不立即响应
            return null;
        }
    }

    // ========== 提交偏移量 ==========
    if (hasCommitOffsetFlag) {
        // 消费者搭车提交了偏移量
        try {
            this.brokerController.getConsumerOffsetManager().commitOffset(
                channel.remoteAddress().toString(),
                requestHeader.getConsumerGroup(),
                requestHeader.getTopic(),
                requestHeader.getQueueId(),
                requestHeader.getCommitOffset());
        } catch (Exception e) {
            log.error("commit offset exception", e);
        }
    }

    // ========== 设置消息体 ==========
    if (getMessageResult.getStatus() == GetMessageStatus.FOUND) {
        // 设置消息体
        response.setBody(getMessageResult.getBufferList());
    }

    return response;
}
```

```java
    /**
     * 挂起一个 Pull 请求
     */
    public void suspendPullRequest(final String topic, final int queueId,
            final PullRequest pullRequest) {
        String key = this.buildKey(topic, queueId);
        ManyPullRequest mpr = this.pullRequestTable.get(key);
        if (null == mpr) {
            mpr = new ManyPullRequest();
            ManyPullRequest prev = this.pullRequestTable.putIfAbsent(key, mpr);
            if (prev != null) {
                mpr = prev;
            }
        }

        mpr.addPullRequest(pullRequest);
    }

        return topic + TOPIC_QUEUEID_SEPARATOR + queueId;

     */
    @Override
    public void run() {
        log.info("{} service started", this.getServiceName());
        while (!this.isStopped()) {
            try {
                // 等待 5 秒或被唤醒
                if (this.brokerController.getBrokerConfig().isLongPollingEnable()) {
                    this.waitForRunning(5 * 1000);
                } else {
                    this.waitForRunning(
                        this.brokerController.getBrokerConfig()
                            .getShortPollingTimeMills());
                }

                // 检查所有挂起的请求
                this.checkHoldRequest();
            } catch (InterruptedException e) {
                // ...
            } catch (Throwable e) {
                log.error("checkHoldRequest exception", e);
            }
        }

    }
```

```java
// PullRequestHoldService.java
private void checkHoldRequest() {
    for (String key : this.pullRequestTable.keySet()) {
        String[] kArray = key.split(TOPIC_QUEUEID_SEPARATOR);
        if (kArray.length == 2) {
            String topic = kArray[0];
            int queueId = Integer.parseInt(kArray[1]);

            // 获取该队列的最大 offset
            final long offset = this.brokerController
                .getMessageStore()
                .getMaxOffsetInQueue(topic, queueId);

            try {
                // 通知消息到达
                this.notifyMessageArriving(topic, queueId, offset);
            } catch (Throwable e) {
                log.error("checkHoldRequest, notifyMessageArriving", e);
            }
        }
    }
}

/**
 * 通知消息到达
 */
public void notifyMessageArriving(final String topic, final int queueId,
        final long maxOffset) {
    notifyMessageArriving(topic, queueId, maxOffset, null, 0, null, null);
}

public void notifyMessageArriving(final String topic, final int queueId,
        final long maxOffset, final Long tagsCode, final long msgStoreTime,
        final byte[] filterBitMap, final Map<String, String> properties) {

    String key = this.buildKey(topic, queueId);
    ManyPullRequest mpr = this.pullRequestTable.get(key);
    if (mpr != null) {
        // 获取所有挂起的请求
        List<PullRequest> requestList = mpr.cloneListAndClear();
        if (requestList != null && !requestList.isEmpty()) {
            for (PullRequest request : requestList) {
                // 检查是否有新消息到达
                if (request.getMaxOffset() < maxOffset) {
                    // 有新消息
                    if (messageFilter != null) {
                        // 检查 TAG 过滤
                        if (!messageFilter.isMatchedByConsumeQueue(
                                tagsCode, filterBitMap)) {
                            continue;  // 不匹配，继续挂起
                        }
                    }

                    // 唤醒请求：重新执行处理
                    try {
                        this.brokerController.getPullMessageProcessor()
                            .executeRequestWhenWakeup(
                                request.getClientChannel(),
                                request.getRequestCommand());
                    } catch (Throwable e) {
                        log.error("executeRequestWhenWakeup exception", e);
                    }

                    continue;
                }

                // 检查是否超时
                if (System.currentTimeMillis() >=
                        (request.getSuspendTimestamp() + request.getTimeoutMillis())) {
                    // 超时，唤醒请求
                    try {
                        this.brokerController.getPullMessageProcessor()
                            .executeRequestWhenWakeup(
                                request.getClientChannel(),
                                request.getRequestCommand());
                    } catch (Throwable e) {
                        log.error("executeRequestWhenWakeup timeout", e);
                    }

                    continue;
                }

                // 既没有新消息，也没超时，重新加入挂起列表
                mpr.addPullRequest(request);
            }

            // 如果还有挂起请求，重新放入表
            if (mpr.isListEmpty()) {
                this.pullRequestTable.remove(key);
            }
        }
    }
}
```

```java
// PullMessageProcessor.java
public void executeRequestWhenWakeup(final Channel channel,
        final RemotingCommand request) throws RemotingException {

    // 创建 Runnable，异步执行
    Runnable run = new Runnable() {
        @Override
        public void run() {
            try {
                // 重新执行 processRequest
                // 注意：brokerAllowSuspend = false（不再允许挂起）
                final RemotingCommand response = PullMessageProcessor.this
                    .processRequest(channel, request, false);

                if (response != null) {
                    // 设置 opaque 与请求匹配
                    response.setOpaque(request.getOpaque());
                    response.markResponseType();
                    try {
                        // 写回响应
                        channel.writeAndFlush(response).addListener(
                            new ChannelFutureListener() {
                                @Override
                                public void operationComplete(
                                        ChannelFuture future) throws Exception {
                                    if (!future.isSuccess()) {
                                        log.error("processRequest error, "
                                            + future.cause());
                                    }
                                }
                            });
                    } catch (Throwable e) {
                        log.error("processRequest error", e);
                    }
                }
            } catch (RemotingProcessException | RemotingCommandException e) {
                log.error("executeRequestWhenWakeup exception", e);
            }
        }
    };

    // 提交到线程池异步执行
    this.brokerController.getPullMessageExecutor().submit(run);
}
```

### 13.7 长轮询超时机制

如果 5 秒内没有新消息到达，`checkHoldRequest` 会检查所有挂起的请求是否超时：

```
挂起超时 = suspendTimestamp + timeoutMillis

默认 suspendTimeoutMillisLong = 15 * 1000 (15秒)
```

超时后，`executeRequestWhenWakeup` 被调用，`brokerAllowSuspend=false`，Broker 会立即返回 `PULL_NOT_FOUND` 响应给消费者，消费者收到后再次发起 Pull 请求。

## 14. ConsumeMessageOrderlyService 顺序消费

### 14.1 顺序消费概述

顺序消费（Orderly Consumption）确保同一个 MessageQueue 中的消息被同一个线程顺序消费。与并发消费相比：

1. **分布式锁**：消费者需要对 MessageQueue 加锁，确保同一时间只有一个消费者消费某个队列
2. **本地锁**：同一个消费者内，对同一队列的消息加本地锁
3. **消费失败处理**：不发送回重试队列，而是本地重试（`SUSPEND_CURRENT_QUEUE_A_MOMENT`）

#### lockMQPeriodically 分布式锁（每 20 秒）

```java
// ConsumeMessageOrderlyService.java
public void lockMQPeriodically() {
    if (!this.defaultMQPushConsumerImpl.isConsumeOrderly()) {
        return;
    }

    // 获取所有分配到的 MessageQueue
    Set<MessageQueue> messageQueueSet = this.defaultMQPushConsumerImpl
        .getRebalanceImpl().getProcessQueueTable().keySet();

    if (messageQueueSet.isEmpty()) {
        return;
    }

    // 向 Broker 批量请求锁
    this.lockMQ(messageQueueSet);
}

public boolean lockMQ(final Set<MessageQueue> mqs) {
    // 按 BrokerName 分组
    Map<String, Set<MessageQueue>> brokerMqs = this.groupMessageQueueByBroker(mqs);

    // 对每个 Broker 发送 LOCK_BATCH_MQ 请求
    for (Map.Entry<String, Set<MessageQueue>> entry : brokerMqs.entrySet()) {
        String brokerAddr = entry.getKey();
        Set<MessageQueue> mqSet = entry.getValue();

        try {
            // 发送批量加锁请求
            Set<MessageQueue> lockOKMqs = this.defaultMQPushConsumerImpl
                .getmQClientFactory()
                .getMQClientAPIImpl()
                .lockBatchMQ(brokerAddr, mqSet, 3000);

            // 更新锁状态
            for (MessageQueue mq : lockOKMqs) {
                ProcessQueue processQueue = this.defaultMQPushConsumerImpl
                    .getRebalanceImpl().getProcessQueue(mq);
                if (processQueue != null) {
                    processQueue.setLocked(true);
                    processQueue.setLastLockTimestamp(System.currentTimeMillis());
                }
            }

            // 未加锁成功的设为未锁定
            for (MessageQueue mq : mqs) {
                if (!lockOKMqs.contains(mq)) {
                    ProcessQueue processQueue = this.defaultMQPushConsumerImpl
                        .getRebalanceImpl().getProcessQueue(mq);
                    if (processQueue != null) {
                        processQueue.setLocked(false);
                    }
                }
            }
        } catch (Exception e) {
```

```java
public class MessageQueueLock {
    // 每个 MessageQueue 对应一个锁对象
    private ConcurrentMap<MessageQueue, Object> mqLockTable =
        new ConcurrentHashMap<>();

    /**
     * 获取锁对象

    public Object fetchLockObject(final MessageQueue mq) {

            if (prev != null) {
                lock = prev;
            }
        }
        return lock;
    }

     * 尝试获取锁
     */
    public boolean tryLock(final MessageQueue mq) {
        Object lock = fetchLockObject(mq);
        return Thread.holdsLock(lock);
    }

        synchronized (lock) {
            // 获取锁
        }
    }

     * 释放锁

    public void unlock(final MessageQueue mq) {
        Object lock = mqLockTable.get(mq);

        }
    }
```

### 14.4 ConsumeRequest 顺序消费任务

```java
// ConsumeMessageOrderlyService.java
class ConsumeRequest implements Runnable {
    private final ProcessQueue processQueue;
    private final MessageQueue messageQueue;

    public ConsumeRequest(ProcessQueue processQueue, MessageQueue messageQueue) {
        this.processQueue = processQueue;
        this.messageQueue = messageQueue;
    }

    @Override
    public void run() {
        if (this.processQueue.isDropped()) {
            log.info("the message queue not be able to consume, because it's dropped, {}",
                this.messageQueue);
            return;
        }

        // 获取本地锁
        final Object objLock = messageQueueLock.fetchLockObject(this.messageQueue);
        synchronized (objLock) {
            // 锁定检查
            if (this.processQueue.isLocked() && !this.processQueue.isLockExpired()) {
                // 已获得分布式锁

                long beginTime = System.currentTimeMillis();
                // 循环消费直到队列为空或超过 60 秒
                for (boolean continueConsume = true; continueConsume; ) {
                    if (this.processQueue.isDropped()) {
                        log.warn("the message queue dropped, {}", this.messageQueue);
                        break;
                    }

                    // 消费时间超过 60 秒，退出循环
                    if (System.currentTimeMillis() - beginTime > 60000) {
                        break;
                    }

                    // ProcessQueue 锁检查
                    if (!this.processQueue.isLocked()) {
                        log.warn("the message queue not locked, {}", this.messageQueue);
                        // 延迟 3 秒后重试
                        this.defaultMQPushConsumerImpl.getRebalanceImpl()
                            .unlock(this.messageQueue, false);
                        break;
                    }

                    // 获取消息（从 ProcessQueue 取出，不超过 batchSize）
                    final int batchSize = 1;
                    List<MessageExt> msgs = this.processQueue.takeMessages(
                        this, batchSize);

                    if (msgs.isEmpty()) {
                        // 没有消息，退出循环
                        break;
                    }

                    // 构建消费上下文
                    MessageExt msg = msgs.get(0);
                    long offset = msg.getQueueOffset();

                    // 设置重试 Topic
                    String topic = msg.getTopic();
                    // ...

                    long beginConsumeTime = System.currentTimeMillis();
                    ConsumeOrderlyStatus status = null;

                    try {
                        // 调用用户消息监听器
                        status = messageListener.consumeMessage(
                            msgs, context);
                    } catch (Throwable e) {
                        log.warn("consumeMessage exception", e);
                        status = ConsumeOrderlyStatus.SUSPEND_CURRENT_QUEUE_A_MOMENT;
                    }

                    // 处理消费结果
                    if (status == null) {
                        status = ConsumeOrderlyStatus.SUSPEND_CURRENT_QUEUE_A_MOMENT;
                    }

                    long consumeRT = System.currentTimeMillis() - beginConsumeTime;
                    if (status == ConsumeOrderlyStatus.SUCCESS) {
                        // 消费成功，提交（从 ProcessQueue 移除已消费消息）
                        long commitOffset = this.processQueue.commit();
                        if (commitOffset >= 0) {
                            // 更新偏移量
                            this.defaultMQPushConsumerImpl.getOffsetStore()
                                .updateOffset(this.messageQueue, commitOffset, false);
                        }
                    } else {
                        // 消费失败
                        switch (status) {
                            case SUSPEND_CURRENT_QUEUE_A_MOMENT:
                                // 挂起当前队列一会儿，本地重试
                                if (checkReconsumeTimes(msg)) {
                                    // 将消息放回 ProcessQueue 前面
                                    this.processQueue.makeMessageToConsumeAgain(msgs);
                                } else {
                                    // 超过最大重试次数，提交（跳过）
                                    long commitOffset = this.processQueue.commit();
                                    if (commitOffset >= 0) {
                                        this.defaultMQPushConsumerImpl
                                            .getOffsetStore()
                                            .updateOffset(this.messageQueue,
                                                commitOffset, false);
                                    }
                                }
                                break;
                            case ROLLBACK:
                                // 回滚（放回 msgTreeMap）
                                this.processQueue.rollback();
                                break;
                            default:
                                break;
                        }
                    }

                    // 设置继续消费标志
                    continueConsume = (status == ConsumeOrderlyStatus.SUCCESS
                        && !this.processQueue.isDropped()
                        && this.processQueue.isLocked());
                }
            } else {
                // 未获得分布式锁，延迟尝试
                this.defaultMQPushConsumerImpl.getRebalanceImpl()
                    .lock(this.messageQueue);
            }
        }
    }
}
```

### 14.5 顺序消费消费状态

| 状态 | 说明 | 处理方式 |
|------|------|---------|
| `SUCCESS` | 消费成功 | commit（从 ProcessQueue 移除），更新偏移量 |
| `SUSPEND_CURRENT_QUEUE_A_MOMENT` | 挂起当前队列一会儿 | makeMessageToConsumeAgain（放回前面），本地重试 |
| `ROLLBACK` | 回滚 | rollback（放回 msgTreeMap） |

### 14.6 顺序消费 vs 并发消费对比

| 维度 | 并发消费 | 顺序消费 |
|------|---------|---------|
| 消费顺序 | 不保证顺序 | 同队列内严格顺序 |
| 线程模型 | 多线程并发 | 单线程加锁顺序 |
| 分布式锁 | 不需要 | 需要（LOCK_BATCH_MQ） |
| 本地锁 | 不需要 | 需要（synchronized） |
| 消费失败 | sendMessageBack 到重试队列 | 本地重试（SUSPEND） |
| 消费超时 | 无超时限制 | 60 秒退出消费循环 |
| 消费偏移量 | removeMessage 后更新 | commit 后更新 |
| ProcessQueue | putMessage → removeMessage | takeMessages → commit/rollback |

```
                                                  → 循环直到空或超时
```

```java
// ConsumerManager.java
public boolean registerConsumer(final String group, final ClientChannelInfo clientChannelInfo,
        ConsumeType consumeType, MessageModel messageModel,
        ConsumeFromWhere consumeFromWhere, final Set<SubscriptionData> subList,
        boolean isNotifyConsumerIdsChangedEnable) {

    // 获取或创建 ConsumerGroupInfo
    ConsumerGroupInfo consumerGroupInfo = this.consumerTable.get(group);
    if (null == consumerGroupInfo) {
        ConsumerGroupInfo tmp = new ConsumerGroupInfo(
            group, consumeType, messageModel, consumeFromWhere);
        ConsumerGroupInfo prev = this.consumerTable.putIfAbsent(group, tmp);
        consumerGroupInfo = prev != null ? prev : tmp;
    }

    boolean updateChannelRsp = false;
    boolean updateSubscriptionRsp = false;

    // 更新通道信息
    boolean updated = consumerGroupInfo.updateChannel(
        clientChannelInfo, consumeType, messageModel, consumeFromWhere);
    if (updated) {
        updateChannelRsp = true;
    }

    // 更新订阅信息
    updated = consumerGroupInfo.updateSubscription(subList);
    if (updated) {
        updateSubscriptionRsp = true;
    }

    // 如果有变化，通知所有消费者
    if (updateChannelRsp || updateSubscriptionRsp) {
        if (isNotifyConsumerIdsChangedEnable) {
            // 发送 CONSUMER_IDS_CHANGE 通知
            this.consumerIdsChangeListener.handle(
                ConsumerGroupEvent.CHANGE, group, consumerGroupInfo.getAllChannel());
        }
    }

    // 注册通道事件
    this.clientChannelInfo = clientChannelInfo;

    return updateChannelRsp || updateSubscriptionRsp;
}
```

```java
public void scanNotActiveChannel() {

    Iterator<Map.Entry<String, ConsumerGroupInfo>> it =
        this.consumerTable.entrySet().iterator();
    while (it.hasNext()) {
        Map.Entry<String, ConsumerGroupInfo> entry = it.next();
        String group = entry.getKey();

            consumerGroupInfo.getChannelInfoTable();

        Iterator<Map.Entry<Channel, ClientChannelInfo>> itChannel =
            channelInfoTable.entrySet().iterator();

            Map.Entry<Channel, ClientChannelInfo> channelEntry =
                itChannel.next();
            ClientChannelInfo clientChannelInfo = channelEntry.getValue();

            // 检查最后心跳时间
            if (clientChannelInfo.isExpired(this.channelExpiredTimeout)) {
                // 通道已过期
                itChannel.remove();
                // 触发通道关闭事件
                this.channelEventListener.onChannelClose(
                    channelEntry.getKey(),
                    ChannelEventListener.ChannelCloseReason.OVERTIME,
                    clientChannelInfo.getRemoteAddress());

                log.info("scanNotActiveChannel, remove channel, group={}, {}",
                    group, clientChannelInfo);
            }
        }

        // 如果组中没有通道了，移除整个组
        if (channelInfoTable.isEmpty()) {
            log.info("scanNotActiveChannel, remove group, group={}", group);
            it.remove();
        }
    }
```

## 16. 知识点总结

### 16.1 核心设计思想

1. **Push = Pull + 长轮询**：RocketMQ 的 Push 消费本质是 Pull，通过 Broker 端长轮询实现"准实时"推送效果。消费者主动控制拉取频率，实现天然背压。

2. **Rebalance 动态分配**：通过定时（20s）或事件触发的 Rebalance 机制，动态调整消费者与 MessageQueue 的映射关系，实现负载均衡。

3. **7 道流量控制门**：在 Pull 之前设置多层流控检查（队列丢弃、服务状态、暂停、消息数量、消息大小、跨度、锁），保护消费者不被压垮。

4. **ProcessQueue 本地缓冲**：TreeMap 按 offset 排序存储拉取到的消息，提供并发安全的 put/remove 操作，同时跟踪消息计数和跨度。

5. **偏移量三条提交路径**：搭车提交（Pull 请求携带）、定时提交（5s）、队列移除时提交，确保偏移量及时持久化。

6. **长轮询双重触发**：新消息到达（ReputMessageService → notifyMessageArriving）和超时检查（5s），确保消息及时推送且不会无限挂起。

```
   → 投递到延迟队列              → 下次循环重新消费
          │
   延迟到达后
   → 投递到 %RETRY% 队列
   → 消费者拉取重试消息
          │
   超过最大重试次数 (默认16次)
   → 进入 %DLQ% 死信队列
```

### 16.5 常见问题分析

#### Q1: 为什么 Push 模式不直接推送？

A: 直接推送无法感知消费者处理能力，容易导致消费者积压。Pull 模式让消费者自己控制拉取速率，天然实现背压。加上 Broker 端长轮询，Pull 的延迟可以控制在毫秒级。

#### Q2: Rebalance 会导致消息重复消费吗？

A: 会的。Rebalance 时，如果 ProcessQueue 中还有未消费的消息，这些消息会被丢弃（`setDropped(true)`），新的消费者会从 Broker 记录的偏移量重新拉取。如果旧消费者已经消费但还没提交偏移量，新消费者会重复消费。因此消费端需要实现幂等。

#### Q3: 长轮询挂起的请求会一直占用资源吗？

A: 不会。挂起的请求存在 `PullRequestHoldService` 的内存 Map 中，最多挂起 15 秒。每 5 秒检查一次超时，超时后立即返回。同时新消息到达会立即唤醒。

#### Q4: 顺序消费和并发消费的最大区别是什么？

A: 顺序消费需要分布式锁（确保只有一个消费者消费某个队列）和本地锁（确保单线程消费），消费失败时本地重试而非发回重试队列。并发消费不需要锁，消费失败发回重试队列。顺序消费吞吐量低于并发消费，但保证同一队列内消息顺序。

#### Q5: 偏移量搭车提交的优缺点？

A: 优点是减少 `UPDATE_CONSUMER_OFFSET` RPC 请求，提升效率。缺点是偏移量提交依赖 Pull 请求频率，如果消息没有新增（无 Pull 请求），偏移量可能不会及时提交。

#### Q6: ProcessQueue 的 MaxSpan 流控原理？

A: MaxSpan = msgTreeMap.lastKey() - msgTreeMap.firstKey()，表示缓冲区中消息的 offset 跨度。如果跨度过大（> 2000），说明前面的消息消费慢、后面不断有新消息拉入。暂停拉取可以让消费者先消费前面的消息，避免积压。

### 16.6 消费全链路时序总结

```
1. RebalanceService.run() (每20s)
   → RebalanceImpl.doRebalance()
   → rebalanceByTopic(topic)
   → allocateMessageQueueAveragely.allocate()
   → updateProcessQueueTableInRebalance()
   → dispatchPullRequest(pullRequestList)

2. PullMessageService.run() (单线程循环)
   → messageRequestQueue.take()
   → DefaultMQPushConsumerImpl.pullMessage(pullRequest)
   → [7道流量控制门]
   → pullAPIWrapper.pullKernelImpl(..., ASYNC, pullCallback)
   → MQClientAPIImpl.pullMessageAsync()
   → Netty RemotingClient.invokeAsync()

3. Broker: PullMessageProcessor.processRequest()
   → 权限/订阅检查
   → messageStore.getMessageAsync()
   → DefaultPullMessageResultHandler.handle()
   → FOUND: 返回消息
   → NOT_FOUND + suspend: PullRequestHoldService.suspendPullRequest()

4. 长轮询唤醒:
   → ReputMessageService.doReput()
   → NotifyMessageArrivingListener.arriving()
   → PullRequestHoldService.notifyMessageArriving()
   → executeRequestWhenWakeup() (brokerAllowSuspend=false)
   → 重新 processRequest() → FOUND

5. 消费者收到响应:
   → PullCallback.onSuccess(PullResult)
   → FOUND: processQueue.putMessage(msgs)
   → consumeMessageService.submitConsumeRequest(msgs, pq, mq)
   → 重新入队 PullRequest (executePullRequestImmediately)

6. 消费执行:
   → ConsumeRequest.run()
   → messageListener.consumeMessage(msgs, context)
   → processConsumeResult(status)
   → CONSUME_SUCCESS: removeMessage + updateOffset
   → RECONSUME_LATER: sendMessageBack + removeMessage + updateOffset

7. 偏移量提交:
   → 搭车: pullMessage 时携带 commitOffset
   → 定时: 每5s persistAllConsumerOffset
   → 移除: removeProcessQueue 时 persist
```
