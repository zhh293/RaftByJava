## 一、配置中心（Config Center）

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/config/ConfigCenterConfig.java`

### 核心功能

配置中心用于外部化管理 Dubbo 配置，支持动态配置推送。支持的实现包括 Zookeeper、Nacos、Apollo 等。

### 关键属性

| 属性 | 说明 | 默认值 |
|---|---|---|
| `protocol` | 配置中心协议 | zookeeper |
| `address` | 配置中心地址 | - |
| `namespace` | 命名空间（多租户隔离） | dubbo |
| `group` | 配置分组 | dubbo |
| `timeout` | 连接超时（ms） | 30000 |
| `check` | 启动时检查配置中心是否可用 | true |
| `configFile` | 全局配置文件 key | dubbo.properties |
| `appConfigFile` | 应用级配置文件 key | - |
| `username/password` | 认证信息 | - |

### Spring Boot 配置示例

```yaml
dubbo:
  config-center:
    # 使用 Nacos 作为配置中心
    address: nacos://192.168.1.100:8848
    # 命名空间隔离
    namespace: production
    # 配置分组
    group: dubbo-config
    # 连接超时
    timeout: 30000
    # 启动时不检查（允许配置中心不可用时启动）
    check: false
    # 全局配置文件名
    config-file: dubbo.properties
    # 应用级配置文件名
    app-config-file: application-dubbo.properties
    # 认证
    username: admin
    password: secret123
    # 自定义参数
    parameters:
      config.long-poll.timeout: "30000"
```

### 多配置中心

```yaml
dubbo:
  config-centers:
    primary:
      address: nacos://config1.example.com:8848
      namespace: production
      group: dubbo
    secondary:
      address: zookeeper://config2.example.com:2181
      namespace: production
```

### 配置优先级（从高到低）

1. JVM 系统属性（-D 参数）
2. 外部化配置（配置中心）
3. Spring Boot application.yml
4. Dubbo API / 注解配置

## 二、元数据中心（Metadata Report）

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/config/MetadataReportConfig.java`

### 核心功能

元数据中心存储服务的完整元数据信息（方法签名、参数类型等），用于服务治理、测试、文档生成等场景。与注册中心分离后，注册中心只存储地址信息，减轻注册中心压力。

### 关键属性

| 属性 | 说明 | 默认值 |
|---|---|---|
| `address` | 元数据中心地址 | - |
| `protocol` | 协议 | - |
| `retryTimes` | 连接重试次数 | - |
| `retryPeriod` | 重试间隔（ms） | - |
| `cycleReport` | 是否周期性全量上报 | true |
| `syncReport` | 是否同步上报 | false（异步） |
| `cluster` | 是否集群模式 | - |
| `check` | 启动时检查 | true |
| `reportMetadata` | 是否上报元数据 | - |
| `reportDefinition` | 是否上报服务定义 | - |

### Spring Boot 配置示例

```yaml
dubbo:
  metadata-report:
    address: nacos://192.168.1.100:8848
    # 重试配置
    retry-times: 3
    retry-period: 5000
    # 周期性全量上报（每天）
    cycle-report: true
    # 异步上报（不阻塞主流程）
    sync-report: false
    # 启动时不强制检查
    check: false
    # 上报元数据
    report-metadata: true
    # 上报服务定义
    report-definition: true
    # 分组
    group: metadata
    # 认证
    username: admin
    password: secret
```

### 注册模式配置

```yaml
dubbo:
  registry:
    address: nacos://192.168.1.100:8848
    # 注册模式：instance（应用级）、interface（接口级）、all（两者都注册）
    register-mode: instance
    # 注册中心同时作为元数据中心
    use-as-metadata-center: true
    # 注册中心同时作为配置中心
    use-as-config-center: true
```

## 三、注册中心高级配置

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/config/RegistryConfig.java`

### 完整高级配置

```yaml
dubbo:
  registry:
    address: nacos://192.168.1.100:8848
    # 协议
    protocol: nacos
    # 分组（服务隔离）
    group: dev-group
    # 版本
    version: 1.0.0
    # 连接超时
    timeout: 5000
    # Session 超时（心跳）
    session: 60000
    # 本地缓存文件（注册中心不可用时使用）
    file: /home/dubbo/registry-cache/dubbo-registry.cache
    # 启动时检查注册中心是否可用
    check: true
    # 是否允许动态注册
    dynamic: true
    # 是否注册服务到注册中心
    register: true
    # 是否从注册中心订阅
    subscribe: true
    # 简化注册信息（减少注册中心数据量）
    simplified: true
    # 简化后额外保留的参数
    extra-keys: "retries,owner"
    # 多注册中心时的优先级
    preferred: true
    # 多注册中心时的权重
    weight: 100
    # 区域（zone-aware 路由）
    zone: beijing
    # 集群策略
    cluster: zone-aware
    # 空保护（防止推空地址列表）
    enable-empty-protection: true
    # 接受的协议类型
    accepts: dubbo,tri
    # 注册模式
    register-mode: all
```

### 多注册中心配置

```yaml
dubbo:
  registries:
    # 主注册中心
    primary:
      address: nacos://primary.example.com:8848
      preferred: true
      zone: beijing
      register: true
      subscribe: true
    # 备注册中心
    secondary:
      address: zookeeper://secondary.example.com:2181
      preferred: false
      weight: 50
      zone: shanghai
      register: true
      subscribe: true
```

### 服务级别指定注册中心

```java
// 只注册到 primary 注册中心
@DubboService(registry = "primary")
public class MyServiceImpl implements MyService { }

// 从 secondary 注册中心订阅
@DubboReference(registry = "secondary")
private MyService myService;
```

## 四、链路追踪（Tracing）

### 源码位置

- `dubbo-common/src/main/java/org/apache/dubbo/config/TracingConfig.java`
- `dubbo-common/src/main/java/org/apache/dubbo/config/nested/SamplingConfig.java`
- `dubbo-common/src/main/java/org/apache/dubbo/config/nested/PropagationConfig.java`
- `dubbo-common/src/main/java/org/apache/dubbo/config/nested/ExporterConfig.java`

### 核心功能

Dubbo 内置了分布式链路追踪支持，兼容 OpenTelemetry 和 Zipkin。

### 关键配置

| 属性 | 说明 | 默认值 |
|---|---|---|
| `enabled` | 是否启用追踪 | false |
| `sampling.probability` | 采样率（0.0~1.0） | 0.10 |
| `propagation.type` | 传播类型（W3C / B3） | W3C |
| `tracing-exporter.zipkin-config` | Zipkin 导出配置 | - |
| `tracing-exporter.otlp-config` | OTLP 导出配置 | - |

### Spring Boot 配置示例 - Zipkin

```yaml
dubbo:
  tracing:
    enabled: true
    # 采样配置
    sampling:
      probability: 0.5  # 50% 采样率
    # 传播方式
    propagation:
      type: W3C  # 或 B3（兼容 Zipkin）
    # 导出到 Zipkin
    tracing-exporter:
      zipkin-config:
        endpoint: http://zipkin.example.com:9411/api/v2/spans
        connect-timeout: 1s
        read-timeout: 10s
```

### Spring Boot 配置示例 - OpenTelemetry (OTLP)

```yaml
dubbo:
  tracing:
    enabled: true
    sampling:
      probability: 1.0  # 全量采样（开发环境）
    propagation:
      type: W3C
    # 导出到 OTLP Collector
    tracing-exporter:
      otlp-config:
        endpoint: http://otel-collector.example.com:4318/v1/traces
        timeout: 10s
        compression-method: gzip
        headers:
          Authorization: "Bearer your-token"
```

### Maven 依赖

```xml
<!-- Zipkin 方式 -->
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-tracing-zipkin</artifactId>
</dependency>

<!-- OTLP 方式 -->
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-tracing-otel</artifactId>
</dependency>
```

## 五、泛化调用（Generic Invocation）

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/rpc/service/GenericService.java`

### 核心接口

```java
public interface GenericService {
    // 泛化调用核心方法
    Object $invoke(String method, String[] parameterTypes, Object[] args) throws GenericException;

    // 异步泛化调用
    default CompletableFuture<Object> $invokeAsync(String method, String[] parameterTypes, Object[] args)
            throws GenericException;
}
```

### 使用场景

- 网关/代理层：不需要依赖服务接口 jar 包
- 测试平台：动态调用任意服务
- 服务编排：运行时动态组合服务

### Spring Boot 配置示例

```java
@Configuration
public class GenericConfig {

    /**
     * 方式一：通过 @DubboReference 配置泛化调用
     */
    @DubboReference(
        interfaceName = "com.example.service.UserService",
        generic = "true",  // 启用泛化
        timeout = 5000
    )
    private GenericService userServiceGeneric;

    /**
     * 方式二：通过 ReferenceConfig 编程式配置
     */
    @Bean
    public GenericService orderServiceGeneric() {
        ReferenceConfig<GenericService> reference = new ReferenceConfig<>();
        reference.setInterface("com.example.service.OrderService");
        reference.setGeneric("true");
        reference.setTimeout(5000);
        reference.setRetries(2);
        return reference.get();
    }
}
```

### 泛化调用示例

```java
@RestController
public class GatewayController {

    @DubboReference(interfaceName = "com.example.service.UserService", generic = "true")
    private GenericService userService;

    @PostMapping("/gateway/invoke")
    public Object invoke(@RequestBody InvokeRequest request) {
        // 同步泛化调用
        Object result = userService.$invoke(
            request.getMethod(),           // "getUserById"
            request.getParameterTypes(),   // ["java.lang.Long"]
            request.getArgs()              // [12345L]
        );
        return result;
    }

    @PostMapping("/gateway/invoke-async")
    public CompletableFuture<Object> invokeAsync(@RequestBody InvokeRequest request) {
        // 异步泛化调用
        return userService.$invokeAsync(
            request.getMethod(),
            request.getParameterTypes(),
            request.getArgs()
        );
    }
}
```

### 泛化调用的序列化模式

```yaml
dubbo:
  consumer:
    # generic 的值决定序列化方式：
    # "true" - 默认，使用 Map 表示 POJO
    # "nativejava" - 使用 Java 原生序列化
    # "bean" - 使用 JavaBean 规范序列化
    # "protobuf-json" - 使用 Protobuf JSON 格式
    generic: true
```

## 六、模块化配置（Module Config）

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/config/ModuleConfig.java`

### 核心功能

Dubbo 3.x 支持模块化部署，一个应用可以包含多个模块，每个模块独立管理服务的暴露和引用。

### 关键属性

| 属性 | 说明 | 默认值 |
|---|---|---|
| `background` | 是否后台启动模块 | false |
| `referAsync` | 是否异步引用服务 | - |
| `referThreadNum` | 异步引用线程池大小 | - |
| `exportAsync` | 是否异步暴露服务 | - |
| `exportThreadNum` | 异步暴露线程池大小 | - |
| `checkReferenceTimeout` | 引用检查超时 | - |

### Spring Boot 配置示例

```yaml
dubbo:
  module:
    name: order-module
    version: 1.0.0
    owner: team-order
    # 后台启动（不阻塞 Spring 启动）
    background: true
    # 异步暴露服务
    export-async: true
    export-thread-num: 4
    # 异步引用服务
    refer-async: true
    refer-thread-num: 4
    # 引用检查超时
    check-reference-timeout: 30000
```

## 七、MCP Server 配置（AI 集成）

### 源码位置

`dubbo-common/src/main/java/org/apache/dubbo/config/nested/McpConfig.java`

### 核心功能

Dubbo 支持将服务暴露为 MCP（Model Context Protocol）Server，使 AI Agent 可以直接调用 Dubbo 服务。

### Spring Boot 配置示例

```yaml
dubbo:
  protocol:
    name: tri
    port: 50051
  # Triple 协议下的 MCP 配置
  protocols:
    triple:
      triple:
        mcp:
          enabled: true
          port: 0  # 0 表示复用 Triple 端口
          protocol: streamable  # streamable 或 sse
          session-timeout: 300  # 会话超时（秒）
          path:
            message: /mcp/message
            sse: /mcp/sse
```

## 十、序列化安全配置

### 源码分析

Dubbo 支持的序列化方式（SPI 定义）：

```
# hessian2（默认，Dubbo 协议）
hessian2=org.apache.dubbo.common.serialize.hessian2.Hessian2Serialization

# fastjson2（Triple 协议默认）
fastjson2=org.apache.dubbo.common.serialize.fastjson2.FastJson2Serialization
```

### Spring Boot 配置示例

```yaml
dubbo:
  protocol:
    name: dubbo
    port: 20880
    # 指定序列化方式
    serialization: hessian2
    # 序列化安全：允许/禁止的类
  application:
    # 序列化白名单
    serialize-check-status: WARN  # DISABLE / WARN / STRICT
    # 信任的序列化类（正则）
    trust-serialize-class-level: 2
```

## 十二、最佳实践总结

1. **配置中心与注册中心分离**：生产环境建议将配置中心和注册中心分开部署，避免单点故障
2. **元数据中心异步上报**：使用 `sync-report: false` 避免阻塞服务启动
3. **链路追踪采样率**：生产环境建议 0.01~0.1，开发环境可以设为 1.0
4. **泛化调用安全**：网关使用泛化调用时，务必做好参数校验和权限控制
5. **序列化安全**：生产环境必须开启 STRICT 模式，配置白名单
6. **注册模式选择**：新应用推荐使用 `instance`（应用级注册），减少注册中心压力
7. **空保护**：开启 `enable-empty-protection` 防止注册中心推空导致服务不可用
8. **本地缓存**：配置 `file` 参数，注册中心不可用时可以使用本地缓存
