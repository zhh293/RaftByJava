## 一、集群容错策略（Cluster）

### SPI 定义

```
# dubbo-cluster/src/main/resources/META-INF/dubbo/internal/org.apache.dubbo.rpc.cluster.Cluster
mock=org.apache.dubbo.rpc.cluster.support.wrapper.MockClusterWrapper
scope=org.apache.dubbo.rpc.cluster.support.wrapper.ScopeClusterWrapper
failover=org.apache.dubbo.rpc.cluster.support.FailoverCluster
failfast=org.apache.dubbo.rpc.cluster.support.FailfastCluster
failsafe=org.apache.dubbo.rpc.cluster.support.FailsafeCluster
failback=org.apache.dubbo.rpc.cluster.support.FailbackCluster
forking=org.apache.dubbo.rpc.cluster.support.ForkingCluster
available=org.apache.dubbo.rpc.cluster.support.AvailableCluster
mergeable=org.apache.dubbo.rpc.cluster.support.MergeableCluster
broadcast=org.apache.dubbo.rpc.cluster.support.BroadcastCluster
zone-aware=org.apache.dubbo.rpc.cluster.support.registry.ZoneAwareCluster
```

---

### 1. Failover（失败自动切换，默认）

**行为**：调用失败后自动切换到其他提供者重试。

**关键参数**：
- `retries`：重试次数（不含第一次调用），默认 2

```yaml
dubbo:
  consumer:
    cluster: failover
    retries: 2  # 失败后最多重试 2 次（共调用 3 次）
```

```java
@DubboReference(cluster = "failover", retries = 3)
private UserService userService;

// 方法级别重试
@DubboReference(methods = {
    @Method(name = "findUser", retries = 5),    // 查询方法多重试
    @Method(name = "createUser", retries = 0)   // 写方法不重试
})
private UserService userService;
```

---

### 2. Failfast（快速失败）

**行为**：调用失败立即报错，不重试。

**适用场景**：非幂等操作（如新增记录），避免重复执行。

```java
@DubboReference(cluster = "failfast")
private OrderService orderService;
```

---

### 3. Failsafe（失败安全）

**行为**：调用失败时忽略异常，返回空结果。

**适用场景**：不重要的旁路操作（如写审计日志）。

```java
@DubboReference(cluster = "failsafe")
private AuditLogService auditLogService;
```

---

### 4. Failback（失败自动恢复）

**行为**：调用失败后记录请求，定时重发。

**适用场景**：消息通知等最终一致性场景。

```java
@DubboReference(cluster = "failback")
private NotificationService notificationService;
```

---

### 5. Forking（并行调用）

**行为**：同时调用多个提供者，只要有一个成功就返回。

**关键参数**：
- `forks`：并行调用数量，默认 2

```java
// 源码: ForkingClusterInvoker.java
final int forks = getUrl().getParameter(FORKS_KEY, DEFAULT_FORKS);  // 默认 2
```

```yaml
dubbo:
  consumer:
    cluster: forking
    parameters:
      forks: 3  # 同时调用 3 个提供者
```

```java
@DubboReference(cluster = "forking", parameters = {"forks", "3"})
private CriticalService criticalService;
```

**适用场景**：对实时性要求极高的读操作，用资源换时间。

---

### 6. Broadcast（广播调用）

**行为**：调用所有提供者，任一失败则报错。

**适用场景**：通知所有节点更新缓存、配置等。

```java
@DubboReference(cluster = "broadcast")
private CacheRefreshService cacheRefreshService;
```

---

### 7. Available（可用调用）

**行为**：调用第一个可用的提供者。

---

### 8. Mergeable（合并调用）

**行为**：调用多个分组的提供者，将结果合并返回。

```java
@DubboReference(cluster = "mergeable", merger = "true", group = "*")
private MenuService menuService;  // 合并所有分组的菜单
```

---

### 9. Zone-Aware（区域感知）

**行为**：优先调用同区域的提供者，跨区域作为降级。

```yaml
dubbo:
  consumer:
    cluster: zone-aware
  registry:
    zone: hangzhou  # 当前区域
```

## 二、负载均衡策略（LoadBalance）

### SPI 定义

```
# dubbo-cluster/src/main/resources/META-INF/dubbo/internal/org.apache.dubbo.rpc.cluster.LoadBalance
random=org.apache.dubbo.rpc.cluster.loadbalance.RandomLoadBalance
roundrobin=org.apache.dubbo.rpc.cluster.loadbalance.RoundRobinLoadBalance
leastactive=org.apache.dubbo.rpc.cluster.loadbalance.LeastActiveLoadBalance
consistenthash=org.apache.dubbo.rpc.cluster.loadbalance.ConsistentHashLoadBalance
shortestresponse=org.apache.dubbo.rpc.cluster.loadbalance.ShortestResponseLoadBalance
adaptive=org.apache.dubbo.rpc.cluster.loadbalance.AdaptiveLoadBalance
```

---

### 1. Random（加权随机，默认）

**行为**：按权重随机选择提供者。权重越高被选中概率越大。

```yaml
dubbo:
  consumer:
    loadbalance: random
```

---

### 2. RoundRobin（加权轮询）

**行为**：按权重轮询选择提供者。使用平滑加权轮询算法，避免集中调用。

```java
@DubboReference(loadbalance = "roundrobin")
private DataService dataService;
```

---

### 3. LeastActive（最少活跃调用）

**行为**：选择当前活跃调用数最少的提供者。活跃数 = 已发送请求数 - 已收到响应数。

**适用场景**：让处理能力强的机器自然承担更多请求。

```java
@DubboReference(loadbalance = "leastactive")
private ComputeService computeService;
```

---

### 4. ConsistentHash（一致性哈希）

**行为**：相同参数的请求总是发到同一个提供者。当某个提供者挂掉时，原本发往该提供者的请求会平摊到其他提供者。

**关键参数**：
- `hash.arguments`：参与哈希计算的参数索引，默认第一个参数
- `hash.nodes`：虚拟节点数，默认 160

```java
@DubboReference(loadbalance = "consistenthash",
    parameters = {"hash.arguments", "0,1", "hash.nodes", "320"})
private CacheService cacheService;
```

**适用场景**：有状态服务、缓存服务。

---

### 5. ShortestResponse（最短响应时间）

**行为**：选择平均响应时间最短的提供者。

```java
@DubboReference(loadbalance = "shortestresponse")
private SearchService searchService;
```

---

### 6. Adaptive（自适应负载均衡，推荐！）

**行为**：基于 P2C（Power of Two Choices）算法 + 自适应指标，综合考虑响应时间、活跃请求数等因素动态选择最优提供者。

```java
// 源码中的 Filter 支持
// dubbo-rpc/dubbo-rpc-api/.../filter/AdaptiveLoadBalanceFilter.java
// 自动收集每次调用的耗时指标，反馈给负载均衡算法
```

```yaml
dubbo:
  consumer:
    loadbalance: adaptive  # 自适应负载均衡
```

**适用场景**：异构集群（机器配置不同）、动态负载变化的场景。

## 三、路由规则（Router）

### SPI 定义

```
# dubbo-cluster/src/main/resources/META-INF/dubbo/internal/org.apache.dubbo.rpc.cluster.router.state.StateRouterFactory
mock=org.apache.dubbo.rpc.cluster.router.mock.MockStateRouterFactory
condition=org.apache.dubbo.rpc.cluster.router.condition.ConditionStateRouterFactory
service=org.apache.dubbo.rpc.cluster.router.condition.config.ServiceStateRouterFactory
app=org.apache.dubbo.rpc.cluster.router.condition.config.AppStateRouterFactory
provider-app=org.apache.dubbo.rpc.cluster.router.condition.config.ProviderAppStateRouterFactory
standard-mesh-rule=org.apache.dubbo.rpc.cluster.router.mesh.route.StandardMeshRuleRouterFactory
script-app=org.apache.dubbo.rpc.cluster.router.script.config.AppScriptRouterFactory
tag=org.apache.dubbo.rpc.cluster.router.tag.TagStateRouterFactory
```

---

### 1. 条件路由（Condition Router）

通过条件表达式过滤提供者列表。

```yaml
# 通过配置中心下发条件路由规则
# 示例：来自 10.20.153.10 的消费者只能调用 10.20.153.11 的提供者
# host = 10.20.153.10 => host = 10.20.153.11
```

---

### 2. 标签路由（Tag Router）

基于标签进行流量隔离，常用于灰度发布。

```java
// Provider 端打标签
@DubboService(tag = "gray")
public class GrayDemoServiceImpl implements DemoService { }

// Consumer 端指定标签
RpcContext.getClientAttachment().setAttachment("dubbo.tag", "gray");
demoService.sayHello("world");
```

```yaml
# 通过配置中心下发标签路由规则
dubbo:
  provider:
    tag: gray  # 标记为灰度节点
```

---

### 3. Mesh 路由（Service Mesh）

支持标准的 VirtualService + DestinationRule 规则，兼容 Istio 流量治理。

```java
// dubbo-common/.../config/ConsumerConfig.java
private Boolean meshEnable;  // 是否启用 Mesh 模式
```

```yaml
dubbo:
  consumer:
    mesh-enable: true  # 启用 Mesh 模式，流量治理交给 Sidecar
```

## 四、Mock 降级

### 源码分析

```java
// dubbo-rpc/dubbo-rpc-api/.../Constants.java
String MOCK_KEY = "mock";
String RETURN_PREFIX = "return ";
String THROW_PREFIX = "throw";
String FAIL_PREFIX = "fail:";
String FORCE_PREFIX = "force:";
```

### 配置方式

```java
// 方式一：指定 Mock 类
@DubboReference(mock = "com.example.DemoServiceMock")
private DemoService demoService;

// 方式二：直接返回值
@DubboReference(mock = "return null")
private DemoService demoService;

// 方式三：强制 Mock（不调用远程）
@DubboReference(mock = "force:return empty")
private DemoService demoService;

// 方式四：失败时 Mock
@DubboReference(mock = "fail:return null")
private DemoService demoService;

// 方式五：抛出异常
@DubboReference(mock = "throw com.example.MyException")
private DemoService demoService;
```

### Mock 类实现

```java
public class DemoServiceMock implements DemoService {
    @Override
    public String sayHello(String name) {
        // 降级逻辑：返回缓存数据、默认值等
        return "Mock: Service is unavailable, returning default value";
    }
}
```

## 五、综合配置示例

```yaml
dubbo:
  consumer:
    # 集群容错
    cluster: failover
    retries: 2
    # 负载均衡
    loadbalance: adaptive    # 自适应负载均衡
    # 超时
    timeout: 3000

  # 针对不同服务使用不同策略
  references:
    # 查询服务：多重试 + 一致性哈希
    userQueryService:
      interface: com.example.UserQueryService
      cluster: failover
      retries: 3
      loadbalance: consistenthash
      parameters:
        hash.arguments: "0"

    # 写入服务：快速失败 + 不重试
    orderCreateService:
      interface: com.example.OrderCreateService
      cluster: failfast
      retries: 0
      loadbalance: leastactive

    # 通知服务：失败安全 + Mock 降级
    notificationService:
      interface: com.example.NotificationService
      cluster: failsafe
      mock: "return null"

    # 关键服务：并行调用
    paymentService:
      interface: com.example.PaymentService
      cluster: forking
      parameters:
        forks: "2"
      timeout: 5000
```

## 六、最佳实践

1. **读操作用 failover + 多重试**：查询是幂等的，重试安全
2. **写操作用 failfast + 不重试**：避免重复写入
3. **旁路操作用 failsafe**：日志、监控等不影响主流程
4. **关键路径用 forking**：用资源换可靠性
5. **灰度发布用 tag router**：精确控制流量走向
6. **异构集群用 adaptive 负载均衡**：自动适应不同机器能力
7. **有状态服务用 consistenthash**：保证同一请求到同一节点
8. **所有服务都配 mock**：降级兜底，防止级联故障
