### 1. FixedThreadPool（固定线程池，默认）

```java
// dubbo-common/.../threadpool/support/fixed/FixedThreadPool.java
public class FixedThreadPool implements ThreadPool {
    @Override
    public Executor getExecutor(URL url) {
        String name = url.getParameter(THREAD_NAME_KEY, DEFAULT_THREAD_NAME);
        int threads = url.getParameter(THREADS_KEY, DEFAULT_THREADS);  // 默认 200
        int queues = url.getParameter(QUEUES_KEY, DEFAULT_QUEUES);     // 默认 0

        BlockingQueue<Runnable> blockingQueue;
        if (queues == 0) {
            blockingQueue = new SynchronousQueue<>();        // 不排队，直接交给线程
        } else if (queues < 0) {
            blockingQueue = new MemorySafeLinkedBlockingQueue<>();  // 无界队列（内存安全）
        } else {
            blockingQueue = new LinkedBlockingQueue<>(queues);       // 有界队列
        }

        return new ThreadPoolExecutor(threads, threads, 0, TimeUnit.MILLISECONDS,
                blockingQueue, new NamedInternalThreadFactory(name, true),
                new AbortPolicyWithReport(name, url));  // 拒绝策略：打印线程堆栈+抛异常
    }
}
```

**特点**：线程数固定，核心线程数 = 最大线程数。适合负载稳定的场景。

---

### 2. CachedThreadPool（缓存线程池）

**特点**：核心线程数为 0，最大线程数可配置（默认 Integer.MAX_VALUE），空闲线程存活 1 分钟后回收。适合请求量波动大的场景，但有 OOM 风险。

---

### 3. LimitedThreadPool（有限线程池）

**特点**：与 Cached 类似，但线程一旦创建就不会回收（keepAliveTime = Long.MAX_VALUE）。只增不减，避免频繁创建销毁线程的开销。

---

### 4. EagerThreadPool（急切线程池，重点！）

```java
// dubbo-common/.../threadpool/support/eager/EagerThreadPool.java
public class EagerThreadPool implements ThreadPool {
    @Override
    public Executor getExecutor(URL url) {
        String name = url.getParameter(THREAD_NAME_KEY, DEFAULT_THREAD_NAME);
        int cores = url.getParameter(CORE_THREADS_KEY, DEFAULT_CORE_THREADS);
        int threads = url.getParameter(THREADS_KEY, Integer.MAX_VALUE);
        int queues = url.getParameter(QUEUES_KEY, DEFAULT_QUEUES);
        int alive = url.getParameter(ALIVE_KEY, DEFAULT_ALIVE);

        TaskQueue<Runnable> taskQueue = new TaskQueue<>(queues <= 0 ? 1 : queues);
        EagerThreadPoolExecutor executor = new EagerThreadPoolExecutor(
                cores, threads, alive, TimeUnit.MILLISECONDS,
                taskQueue, new NamedInternalThreadFactory(name, true),
                new AbortPolicyWithReport(name, url));
        taskQueue.setExecutor(executor);
        return executor;
    }
}
```

**核心行为**：当核心线程都忙时，**优先创建新线程**而不是放入队列。只有当线程数达到最大值时才放入队列。这与标准 ThreadPoolExecutor 的行为相反（标准行为是先入队再创建线程）。

**适用场景**：对延迟敏感的服务，希望尽快有线程处理请求。

---

### 5. VirtualThreadPool（虚拟线程池，JDK 21+）

```java
// dubbo-plugin/dubbo-plugin-loom/.../VirtualThreadPool.java
public class VirtualThreadPool implements ThreadPool {
    @Override
    public Executor getExecutor(URL url) {
        String name = url.getParameter(THREAD_NAME_KEY, DEFAULT_THREAD_NAME);
        int threads = url.getParameter(THREADS_VIRTUAL_CORE, 0);
        if (threads > 0) {
            return new ThreadPoolExecutor(threads, Integer.MAX_VALUE, 0L,
                    TimeUnit.MILLISECONDS, new SynchronousQueue<>(),
                    Thread.ofVirtual().name(name, 1).factory());
        } else {
            return Executors.newThreadPerTaskExecutor(
                    Thread.ofVirtual().name(name, 1).factory());
        }
    }
}
```

**特点**：利用 JDK 21 的虚拟线程（Project Loom），每个请求一个虚拟线程，极大提升并发能力，特别适合 IO 密集型服务。

## 二、消息派发策略（Dispatcher）

### SPI 定义

```
# dubbo-remoting/dubbo-remoting-api/.../org.apache.dubbo.remoting.Dispatcher
all=org.apache.dubbo.remoting.transport.dispatcher.all.AllDispatcher
direct=org.apache.dubbo.remoting.transport.dispatcher.direct.DirectDispatcher
message=org.apache.dubbo.remoting.transport.dispatcher.message.MessageOnlyDispatcher
execution=org.apache.dubbo.remoting.transport.dispatcher.execution.ExecutionDispatcher
connection=org.apache.dubbo.remoting.transport.dispatcher.connection.ConnectionOrderedDispatcher
```

---

### 1. AllDispatcher（默认）

```java
// AllChannelHandler.java
public class AllChannelHandler extends WrappedChannelHandler {
    @Override
    public void connected(Channel channel) throws RemotingException {
        ExecutorService executor = getSharedExecutorService();
        executor.execute(new ChannelEventRunnable(channel, handler, ChannelState.CONNECTED));
    }

    @Override
    public void received(Channel channel, Object message) throws RemotingException {
        ExecutorService executor = getPreferredExecutorService(message);
        executor.execute(new ChannelEventRunnable(channel, handler, ChannelState.RECEIVED, message));
    }
    // disconnected, caught 也都派发到线程池
}
```

**行为**：所有事件（连接、断开、请求、响应、异常）全部派发到业务线程池处理。IO 线程只负责读写。

---

### 2. DirectDispatcher

**行为**：所有事件都在 IO 线程上直接处理，不派发到线程池。适合处理极快的逻辑，避免线程切换开销，但会阻塞 IO 线程。

---

### 3. MessageOnlyDispatcher

**行为**：只有请求/响应消息派发到线程池，连接/断开/异常事件在 IO 线程处理。

---

### 4. ExecutionDispatcher

**行为**：只有请求消息派发到线程池，响应/连接/断开/异常都在 IO 线程处理。

---

### 5. ConnectionOrderedDispatcher

**行为**：连接/断开事件放入单独的有序队列（保证连接事件的顺序性），请求/响应派发到线程池。

## 四、Spring Boot 完整配置示例

### Provider 端线程池配置

```yaml
dubbo:
  protocol:
    name: dubbo
    port: 20880
    # 线程池类型
    threadpool: fixed       # 可选: fixed(默认), cached, limited, eager, virtual(JDK21+)
    # 线程池参数
    threads: 500            # 最大线程数（fixed/eager/limited 生效）
    corethreads: 100        # 核心线程数（eager/cached 生效）
    queues: 1000            # 队列大小（0=SynchronousQueue, <0=无界, >0=有界）
    alive: 60000            # 空闲线程存活时间(ms)（cached/eager 生效）
    # IO 线程数
    iothreads: 8            # Netty IO 线程数，默认 CPU+1（最大32）
    # 消息派发策略
    dispatcher: all         # 可选: all(默认), direct, message, execution, connection
    # 线程池耗尽监听器
    thread-pool-exhausted-listeners: org.apache.dubbo.common.threadpool.event.ThreadPoolExhaustedListener
  provider:
    threadpool: eager       # Provider 级别覆盖
    threads: 300
    iothreads: 16
    alive: 120000
    queues: 500
    dispatcher: execution   # 只派发请求消息到线程池
```

### Consumer 端线程池配置

```yaml
dubbo:
  consumer:
    threadpool: cached      # 消费端线程池
    corethreads: 0
    threads: 100
    queues: 0
```

## 五、线程池隔离（服务级别线程池）

Dubbo 支持为不同服务配置独立的线程池，避免慢服务拖垮整个线程池。

### 源码依据

```java
// dubbo-common/.../org.apache.dubbo.rpc.executor.IsolationExecutorSupportFactory
// 支持服务级别的线程池隔离
```

### Spring Boot 配置示例

```yaml
dubbo:
  application:
    executor-management-mode: isolation  # 可选: default(共享), isolation(隔离)
```

```java
// 通过注解为特定服务配置独立线程池
@DubboService(executor = "myExecutor")
public class HeavyServiceImpl implements HeavyService {
    // 这个服务使用独立线程池，不影响其他服务
}
```

## 六、AbortPolicyWithReport 拒绝策略

当线程池满时，Dubbo 不是简单地抛出 RejectedExecutionException，而是使用自定义的 `AbortPolicyWithReport`：

1. **打印告警日志**（包含线程池状态）
2. **导出线程堆栈**到文件（用于排查问题）
3. **抛出 RejectedExecutionException**

这个行为可以通过 `dumpDirectory` 配置导出目录：

```yaml
dubbo:
  application:
    dump-directory: /tmp/dubbo-dump  # 线程池满时堆栈导出目录
    dump-enable: true                # 是否启用导出
```

## 七、最佳实践建议

1. **生产环境推荐 `fixed` 或 `eager`**：fixed 稳定可控，eager 对延迟更友好
2. **队列大小建议设为有限值**：避免 OOM，建议 100-1000
3. **IO 线程数不要设太大**：一般 CPU 核数即可，IO 线程只做读写
4. **高并发场景考虑 `execution` 派发**：减少连接事件对业务线程池的干扰
5. **JDK 21+ 强烈推荐 `virtual`**：虚拟线程对 IO 密集型服务提升巨大
6. **关键服务使用线程池隔离**：防止慢服务雪崩
