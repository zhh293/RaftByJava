## 一、延迟暴露（Delay Export）

### 源码分析

```java
// dubbo-config/dubbo-config-api/.../ServiceConfig.java (第 325-404 行)
public void export(RegisterTypeEnum registerType) {
    // ...
    if (this.shouldExport()) {
        this.init();
        if (shouldDelay()) {
            // 延迟暴露：通过 ScheduledExecutor 延迟执行
            doDelayExport();
        } else {
            doExport(registerType);
        }
    }
}

protected void doDelayExport() {
    ExecutorRepository.getInstance(getScopeModel().getApplicationModel())
            .getServiceExportExecutor()
            .schedule(() -> {
                doExport(RegisterTypeEnum.AUTO_REGISTER);
            }, getDelay(), TimeUnit.MILLISECONDS);
}
```

```java
// dubbo-common/.../config/AbstractServiceConfig.java
protected Integer delay;  // 延迟暴露时间（毫秒）
```

### 工作原理

- `delay > 0`：服务启动后延迟指定毫秒数再暴露服务，给应用预热时间
- `delay = -1`：手动注册模式，需要通过 API 手动触发注册
- `delay = null 或 0`：立即暴露（默认行为）

### Spring Boot 配置示例

```yaml
dubbo:
  provider:
    delay: 5000  # 所有服务延迟 5 秒暴露
```

```java
// 单个服务级别配置
@DubboService(delay = 10000)  // 该服务延迟 10 秒暴露
public class HeavyInitServiceImpl implements HeavyInitService {
    @PostConstruct
    public void init() {
        // 耗时初始化操作（加载缓存、预热连接池等）
    }
}
```

## 二、服务预热（Warmup）

### 源码分析

```java
// dubbo-common/.../config/AbstractServiceConfig.java
private Integer warmup;  // 预热时间（毫秒）
```

预热机制在负载均衡中生效。当一个服务提供者刚启动时，其权重会随时间线性增长，直到达到配置的 `weight` 值。

### 工作原理

负载均衡计算权重时：
```
实际权重 = 配置权重 × (已运行时间 / 预热时间)
```

例如：配置 weight=100, warmup=600000(10分钟)，启动 3 分钟后实际权重 = 100 × (180000/600000) = 30

### Spring Boot 配置示例

```yaml
dubbo:
  provider:
    warmup: 600000   # 预热时间 10 分钟
    weight: 100      # 最终权重
```

```java
@DubboService(warmup = 300000, weight = 100)  // 5 分钟预热
public class CacheServiceImpl implements CacheService {
    // 服务启动后需要时间加载缓存，预热期间少分配流量
}
```

## 三、懒连接（Lazy Connect）

### 源码分析

```java
// dubbo-common/.../config/AbstractReferenceConfig.java
protected Boolean lazy;  // 是否懒连接
```

```java
// dubbo-common/.../constants/CommonConstants.java
String LAZY_CONNECT_KEY = "lazy";
```

### 工作原理

- `lazy=false`（默认）：消费端启动时立即与所有提供者建立长连接
- `lazy=true`：消费端启动时不建立连接，等到第一次调用时才建立连接

### 适用场景

- 服务提供者数量很多，启动时建立大量连接耗时
- 某些服务调用频率很低，不需要预先建立连接
- 加速消费端启动速度

### Spring Boot 配置示例

```yaml
dubbo:
  consumer:
    lazy: true  # 全局懒连接
```

```java
@DubboReference(lazy = true)  // 单个引用懒连接
private RarelyUsedService rarelyUsedService;
```

## 四、连接数控制（Connections）

### 源码分析

```java
// dubbo-common/.../config/AbstractInterfaceConfig.java
protected Integer connections;  // 连接数限制：0=共享连接，>0=独立连接数
```

```java
// dubbo-remoting/dubbo-remoting-api/.../Constants.java
String CONNECTIONS_KEY = "connections";
```

### 工作原理

- `connections=0`（默认）：所有服务共享一个长连接（Dubbo 协议默认单一长连接）
- `connections=N`：为该服务创建 N 个独立连接

### 共享连接数（Consumer 端）

```java
// dubbo-common/.../config/ConsumerConfig.java
private Integer shareconnections;  // 共享连接数，默认 1
```

### Spring Boot 配置示例

```yaml
dubbo:
  consumer:
    connections: 0           # 使用共享连接（默认）
    shareconnections: 3      # 共享连接数设为 3（提升吞吐量）
```

```java
// 高吞吐服务使用独立多连接
@DubboReference(connections = 5)  // 为该服务建立 5 个独立连接
private HighThroughputService highThroughputService;
```

## 七、心跳检测（Heartbeat）

### 源码分析

```java
// dubbo-remoting/dubbo-remoting-api/.../Constants.java
String HEARTBEAT_KEY = "heartbeat";
int DEFAULT_HEARTBEAT = 60 * 1000;           // 默认心跳间隔 60 秒
String HEARTBEAT_TIMEOUT_KEY = "heartbeat.timeout";
int HEARTBEAT_CHECK_TICK = 3;                // 每个心跳周期检查 3 次
long LEAST_HEARTBEAT_DURATION = 1000;        // 最小心跳间隔 1 秒
String IDLE_TIMEOUT_KEY = "idle.timeout";
int DEFAULT_IDLE_TIMEOUT = 600 * 1000;       // 空闲超时 600 秒
```

### 工作原理

1. 客户端和服务端都会定时发送心跳
2. 如果超过 `heartbeat.timeout`（默认 heartbeat × 3）没收到心跳，认为连接断开
3. 客户端触发重连，服务端关闭连接

### Spring Boot 配置示例

```yaml
dubbo:
  protocol:
    heartbeat: 30000         # 心跳间隔 30 秒（默认 60 秒）
  provider:
    # 通过 parameters 设置更细粒度的心跳超时
    parameters:
      heartbeat.timeout: 90000  # 心跳超时 90 秒
```

## 九、后台导出/引用（Background Export/Refer）

### 源码分析

```java
// dubbo-common/.../config/ProviderConfig.java
private Integer exportThreadNum;    // 导出线程数
private Boolean exportBackground;  // 是否后台导出

// dubbo-common/.../config/ConsumerConfig.java
private Integer referThreadNum;     // 引用线程数
private Boolean referBackground;   // 是否后台引用
```

### 工作原理

- `exportBackground=true`：服务暴露在后台线程中异步执行，不阻塞主线程启动
- `referBackground=true`：服务引用在后台线程中异步执行

### Spring Boot 配置示例

```yaml
dubbo:
  provider:
    export-background: true    # 后台异步暴露服务
    export-thread-num: 10      # 暴露线程数
  consumer:
    refer-background: true     # 后台异步引用服务
    refer-thread-num: 10       # 引用线程数
```

## 十、启动时检查（Check）

### 源码分析

```java
// dubbo-common/.../config/AbstractReferenceConfig.java
protected Boolean check;  // 启动时检查提供者是否存在
```

### 工作原理

- `check=true`（默认）：启动时检查依赖的服务是否可用，不可用则抛异常阻止启动
- `check=false`：不检查，允许服务不可用时启动（调用时才报错）

### Spring Boot 配置示例

```yaml
dubbo:
  consumer:
    check: false  # 全局关闭启动检查（开发环境常用）
  registry:
    check: false  # 注册中心不可用时也允许启动
```

```java
@DubboReference(check = false)  // 单个服务关闭检查
private OptionalService optionalService;
```

## 十三、综合配置示例：生产环境推荐

```yaml
dubbo:
  application:
    name: my-service
    dump-directory: /var/log/dubbo/dump
    dump-enable: true
    shutwait: 15000  # 优雅停机等待 15 秒

  protocol:
    name: tri
    port: 50051
    threadpool: eager       # 急切线程池，优先创建线程
    threads: 500            # 最大 500 线程
    corethreads: 100        # 核心 100 线程
    queues: 200             # 队列 200
    alive: 60000            # 空闲 60 秒回收
    iothreads: 8            # IO 线程 8 个
    dispatcher: execution   # 只派发请求到线程池
    payload: 16777216       # 16MB
    heartbeat: 30000        # 30 秒心跳
    accepts: 2000           # 最大 2000 连接

  provider:
    delay: 5000             # 延迟 5 秒暴露（等待缓存预热）
    warmup: 300000          # 5 分钟预热
    weight: 100
    export-background: true # 后台暴露

  consumer:
    check: false            # 开发环境关闭检查
    lazy: true              # 懒连接
    timeout: 3000           # 3 秒超时
    shareconnections: 3     # 共享 3 个连接
    reconnect: "2000"       # 2 秒重连
    refer-background: true  # 后台引用
```
